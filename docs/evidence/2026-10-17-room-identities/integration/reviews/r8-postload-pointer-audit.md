# R8 post-load pointer audit

Classification: the retained R8 scripts contain a concrete asynchronous selection race. They do not yet prove a persistent production pointer defect. The missing evidence is a settled mouse-only selection attempt, with no intervening keyboard or pointer input. No production patch is justified by these receipts alone.

This audit read source and retained logs only. It did not operate the browser, change source, run tests or builds, change dependencies, or alter Git state. R8 owns the live browser and delivery documents. The supplied source identity is `dc1a4b6bc` with R7 plus fix1; this audit did not change or independently re-fingerprint the served application. The writing-style-tim, Unslop, and Natural Causes writing instructions were applied. The documentation scan included the wall-tool design, input design, relevant click-suppression lessons, and the prior wall-probe review. The memory registry search returned no relevant pointer-lifecycle guidance.

## What the retained evidence establishes

1. `.local-build/r8-retained-exit-case.js:16` awaits `page.mouse.click`, then immediately sends `w` or `Delete`. There is no wait for selection between them. Its line 17 waits for a native edit result only after that key. `.local-build/r8-retained-exit-case.log` records a 30-second `waitForFunction` timeout without identifying the guard that prevented selection.
2. `.local-build/r8-first-wall-diagnosis.log` has the same ordering. It clicks, reads `#wall-status` immediately, sends `w`, then waits 100 ms. It reports `Choose a line between two floor tiles.` both before and after that key, and `lastWallEditResult()` is null. `page.mouse.click` returning does not await the Promise started by the application's event listener. The key can therefore cancel that selection before the readback resolves.
3. The same log retains a production-helper projection and inverse for edge `{axis:0,x:18,y:2}`, adjacent tiles `[[17,2],[18,2]]`, camera origin approximately `(656,-141.999781)`, scale 1, and a 1440 by 1000 canvas. The helper rejects another inverse edge and requires `elementFromPoint` to return the canvas. Those checks support the coordinates and DOM ownership at measurement time. They do not prove that the application applied the later click.
4. `.local-build/r8-wall-keyboard-diagnosis.log` reports that focusing the stage and pressing ArrowRight selects `No wall on this line.` with Walls active and no open dialog. That demonstrates controller availability at that later moment. From no selection, ArrowRight chooses the lot center, rather than proving selection of edge 18,2 (`web/src/ui/wall-tool.ts:201`). It does not establish the pointer outcome or selected identity.
5. The previously accepted six `W` edit receipts remain evidence for those edits. A `W` result alone does not identify the input that selected the line. Current source has no hover-to-select wall handler: `pointermove` handles tracked camera gestures (`web/src/input.ts:1471`), while `WallTool.choosePoint` is reached by the editing click callback (`web/src/main.ts:2201`). A receipt described as hover plus keyboard needs its actual click/navigation sequence before it can prove mouse selection.

## Exact routing and drop paths

1. The canvas click handler first honors gesture suppression (`web/src/input.ts:1538`), then calls `withPick`. Every normal editing click waits for the displayed GPU pick (`:1362`, `:1544`). `CanvasEditInput.click` receives both the pick and the unrounded floor world point (`:1548`). The wall path eventually uses the world point, but book ownership is checked first (`web/src/main.ts:2200`). An ordinary furniture/person hit or null hit does not itself prevent Walls from choosing the floor line.
2. `withPick` applies only a defined result whose request generation, camera origin, camera scale, canvas dimensions, Build activity, tool mode, and selected Sim still match (`web/src/input.ts:1365-1367`). Every document `pointerdown` increments that generation (`:1607-1608`). Every document `keydown` increments it before checking `defaultPrevented` (`:1616-1618`). Thus an immediate `w` cancels an unresolved click even when another handler already consumed the key. A later unchanged screenshot cannot reverse that cancellation. A rejected GPU Promise logs `Displayed scene selection failed` and reports selection rejection (`:1368-1369`); silent stale results do neither.
3. Main's displayed-pick callback returns undefined during graphics recovery; it also rejects a changed graphics generation, changed lot revision, undefined world pick, or replaced picked person's identity (`web/src/main.ts:2226-2232`). These undefined outcomes are discarded by the input guard. A pick of a book opens book details before Walls (`:2200`); that is a distinct visible routing outcome, not a missing floor-line calculation.
4. `CharacterWorld.pick` snapshots its renderer generation, source, lot revision, scene-target identity, and ownership map (`web/src/render/character/world.ts:131-139`). It returns undefined if closed, lacking a source/view, reset during the read, or stale after the awaited target read. Load explicitly resets this world (`web/src/main.ts:1168`); ordinary frame preparation does not increment its generation. `SceneTarget.pick` copies the displayed identity/depth pixels and awaits GPU buffer mapping (`web/src/render/scene-target.ts:51-64`). No fixed upper bound on that mapping is present in these functions.
5. Tool mode is a primitive value: review, room-selection, or `buildTools.findIndex(...)` (`web/src/main.ts:2195-2196`). Walls is the first member (`:1762`) and therefore yields stable number 0 while active. Equality with 0 is valid. There is no newly allocated object identity to make every wall click stale. A real mode transition during the read is intentionally rejected.
6. Once routed, `choosePoint` refuses inactive, pending, or blocked state and ignores off-lot/nonfinite points (`web/src/ui/wall-tool.ts:56-64`, `:140-143`). `choose` repeats the activity/pending/blocked guard and can delegate a window-owned line (`:146-151`). A successful ordinary selection writes `line`, refreshes preview, writes status, and renders controls (`:153-156`). Main refreshes blocking from overlays/review each frame (`web/src/main.ts:2306-2310`). No native edit result is expected until `W` or a button actually stages a command (`web/src/ui/wall-tool.ts:172-180`).
7. Load updates lot dimensions and clears wall selection/pending state (`web/src/main.ts:1173`; `web/src/ui/wall-tool.ts:248-254`). It marks the camera dirty (`web/src/main.ts:1158`). Camera pan mutates the same live camera reference (`:2176-2180`); rendering applies dirty camera changes and supplies that camera to `CharacterWorld` (`:2349-2361`). A click during an outstanding camera change may be guarded out. A completed historical pan alone does not permanently arm suppression: a new primary pointerdown resets it when no tracked pointer remains (`web/src/input.ts:1437-1440`). The retained logs do not show a stranded pointer or camera change during either readback.

The existing deferred-pick test covers stale camera/mode/tool/world outcomes and a current positive control (`web/tests/input.test.ts:36-52`). Its keyboard case uses Escape. It was inspected, not run; this audit claims no new test result.

## One bounded control for R8

R8 can distinguish the immediate-key race without changing production or adding a debug API:

1. Finish the current keyboard-owned room case first. For the pointer control, use its known clean baseline and enter Walls through real controls. Require the loading/review/modal surfaces to be closed, Walls visibly active, and stage focus. Record fresh native room membership, lot revision, selected Sim, graphics generation, canvas buffer/rect, `characters.snapshot().view`, and camera origin. Recalculate the same accepted production projection/inverse. Require the rendered view and live camera to agree before clicking; do not infer scale only from a previous load.
2. Attach temporary observational capture listeners for `pointerdown`, `pointerup`, `pointercancel`, `click`, and `keydown`, retaining event target, coordinates, pointer ID/type/buttons, timestamp, and default-prevented state. These listeners must not prevent events or call controllers. Send one real mouse click at the validated point. Poll the visible wall selection/status for at most five seconds while sending no key, second click, pan, or focus change. Retain before/after snapshots and a screenshot of the selected adjacent tiles before any `W`. Stop this control on its first failure; do not retry it repeatedly.
3. If that mouse-only control selects the exact intended line, record the first two failed scripts as inconclusive because they issued a key before selection settled. Continue the normal edit only after the exact selection is observed. This proves that control passed; it does not prove every deferred selection race is harmless.
4. If it still fails, retain its event sequence and stable-state snapshots. Then make one timed read through the existing read-only `__terriStress.characters.pick` at the same buffer pixel (`web/src/main.ts:2452`), recording undefined versus null versus hit, any book ownership, errors, and before/after graphics generation/lot/camera/view. This separate pick cannot recover the original callback's result, but distinguishes persistent unavailable/stale GPU readback from an available displayed pick. A null hit is a valid empty-floor result and should still route Walls. Remove the observational listeners in `finally`.

A mouse-only failure with stable mode/camera/selection/revision, a delivered canvas click, no intervening input, no book hit, and an available pick would justify investigating the exact original readback and controller guards. It would still lack the original callback's resolution and internal pending/blocked state; source breakpoints or equally narrow observational instrumentation would then need explicit authorization. Do not change projection, use a second camera, bypass GPU failure with fabricated picks, or claim the pointer repaired.

No minimal production seam fix is proved. If the owner later elects to change rapid click-then-key behavior, preserve stale-world/camera/tool protection and the book-before-build routing explicitly. A regression should hold the pick Promise pending, send the real wall key, resolve the pick, and assert the chosen product behavior. That would be a separate behavior decision, not an authorized patch from this audit.

**Next steps**: R8 can complete its documented keyboard flow, then perform the single mouse-only observational control if pointer classification is still needed. No source change is authorized or required by this report.
