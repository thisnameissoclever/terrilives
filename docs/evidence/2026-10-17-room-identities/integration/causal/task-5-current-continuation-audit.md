# Four current-continuation failures

The four failures expose two current persistence invariants. The two bed tests use supported current content with no book catalogue or reading tuning; its V15 capture reaches a loader that unconditionally requires reading tuning. The two reading tests interrupt an actual reading session, retain a communal episode that no longer meets its saved owner predicate, and save immediately while paused. Neither problem should be hidden by reverting to historical captures or weakening the lifecycle assertions.

This is a read-only source diagnosis. The executed observations are the four `InvalidValue` failures in `integration-native-focus-1-failures.json`. I ran no Cargo commands, tests, builds, or runtime probes. The exact predicates below are traced from source, not instrumented return-site observations.

## Bookless current content is supported

The source supports this classification independently of the failing tests:

1. The compiler reads optional tuning and validates it only when present (`terri-data/src/compile.rs:110-113`); its `ContentPack` result contains an initially empty book list and that optional reading value (`compile.rs:709-711`). `reading: None` is not restricted to frozen published packs.
2. Current constructors initialize room identities unless `is_pre_books_pack` matches (`terri-sim/src/lib.rs:1945-1947,1968-1970`). The bed pack is a separately constructed current pack. V15 capture therefore has the required registry and writes a complete envelope.
3. `save::v6::validate_live_books` already explicitly permits absent reading tuning when the library has no copies or memories (`save/v6.rs:411-424`). The restore route contradicts that policy by demanding a `BookWorld` with reading tuning even for the empty case.

The smallest repair belongs in canonical book validation/restoration, then is used by the current loader. The absent-catalogue branch must require absence of owned copies and memories, retain metadata such as `taste_seed`, `next_copy_id`, and `migration_granted`, and avoid inventing tuning, titles, grants, RNG draws, or new library state. Preserve existing identity/allocator semantics; do not force metadata back to fresh defaults merely because the lists are empty. Validate catalogue inconsistency explicitly rather than silently treating a populated catalogue without tuning as valid. Continue to validate reading journeys, pending operations, and references through their normal strict paths.

Required bookless controls:

1. A current no-book/no-reading empty world loads its own V15 before ticking, with exact envelope and RNG equality. Repeat after adding the bed fixture people and geometry, then run both original progressed tests unchanged in purpose.
2. A saved copy or memory under absent reading tuning is refused transactionally. Add a reading journey or pending book operation without a catalogue and require refusal rather than silent deletion.
3. A normal current catalogue retains its complete existing library validation, including unknown titles, borrower/home references, physical seat claims, and malformed reading state.
4. Frozen pre-books producers remain frozen. This repair must not initialize their modern room state or change their historical wire bytes.

## Reading transition invariant

`social_company::participation` admits an active successful Read journey with a shared-activity action (`social_company.rs:291-327`). `extend_episodes` creates a `CommunalEpisode` with `extensions: 0`, `remaining: 0`, and `completed_novelty: None` even when peers are empty (`social_company.rs:533-551`), then stores it (`social_company.rs:616-620`). A normal read tick can therefore create the row without another person or a completed book. These fixtures explicitly advance one read tick before interruption. `settle_reward` clears earned satisfaction and reward contexts (`reading.rs:915-927`), but leaves this separate communal row intact. The paused maintenance pass retains it solely because the returning journey still exists.

The loader's `ordinary_owner` alternative does not rescue it: it requires a matching target and Eating or StepWork. The duplicate-order case is routing to the shelf with Path; WaitingReturn has no target. The `reading_owner` alternative excludes an early, unextended, unfinished return. The current capture faithfully serializes the live row and strict loading refuses it.

Repair at the transition that makes the row obsolete, or a canonical lifecycle function called synchronously by that transition. Do not filter it out only during serialization, clear every communal row, broaden the loader to accept any retained journey, or wait for the next full tick. Preserve extension counts and completed novelty when needed to validate elapsed work or completed-pass history. A shared predicate can prevent runtime cleanup and saved ownership from drifting, but must continue checking the exact origin/action and the legitimate history conditions.

Required reading controls:

1. Admit a V15 baseline, an active Read snapshot immediately before interruption, and the immediate paused snapshot after each of duplicate-order insertion and cancellation. Record stage, elapsed/session cap, communal target, extensions, remaining, and completed novelty so the execution pass confirms the traced predicate rather than only observing another generic `InvalidValue`.
2. For the early unextended return, require obsolete communal state gone at the transition, exact clock/RNG preservation through the command drain and save/load, and all original copy/order/reservation assertions retained.
3. Include real extended and completed-held reading interrupted into Return/WaitingReturn. Require retained necessary history and strict reload; this guards against blanket row removal.
4. Corrupt the saved communal owner/target or attach unsupported history to an unrelated returning person and require atomic refusal. Preserve malformed reading reward, copy borrower, seat-claim, and target controls.

## Proof limits

The repair pass must establish those operands and baseline admission before reporting the runtime diagnosis as confirmed. No additional failures beyond these four were investigated.
