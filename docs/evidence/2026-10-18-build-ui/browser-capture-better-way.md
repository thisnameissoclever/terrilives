## What was taken as fixed but is not

[F1] The child must own capture. It need not. The child can review saved pixels independently while the root owns the displayed IAB and sequential gameplay. That ownership directly matches the project's displayed-pass contract. This corrects the project's evidence procedure; it does not claim to repair an underlying browser-provider defect.

[F2] Raw CDP device metrics are the viewport mechanism. The selected IAB advertises a browser-scoped `viewport` capability. Its current documented interface is `set({width, height})` and `reset()`. Use that interface for exact breakpoint testing. Its contract does not expose implementation details or promise that arbitrary raw Emulation overrides also resize the screenshot surface. A reported CSS viewport is therefore a separate measurement from the decoded screenshot dimensions. No evidence here establishes how the child pane's physical width was selected.

[F3] Receipt success is capture success. It is not. Geometry, focus, paint and saved bytes must agree. `docs/lessons-learned.md:12654-12659` already requires binding each screenshot to its own measured state and source hash and retaining failed final receipts. Apply that rule before accepting each file.

[F4] Exactly four replacement deliverables means an automated capture loop. It does not. Four sequential state transactions, each fully inspected before the next begins, are simpler and prevent an incorrectly accepted first file from contaminating later claims.
