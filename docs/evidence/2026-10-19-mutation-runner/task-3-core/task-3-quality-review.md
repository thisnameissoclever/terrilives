## Finding

1. **P1: Retain or reject a failed historical aggregate even when it has no snapshot.** In `.github/scripts/mutation_recovery.py:363-369`, `ingest()` retains only preparation jobs and workers from each newly encountered attempt. It ignores `mutation-fixture-aggregate` and `mutation-production-aggregate`. An aggregate exception in `refresh_recovery()` or current-input validation occurs before `.github/scripts/mutation_workflow.py:341` seals the snapshot; the exception handler at `mutation_workflow.py:381-385` writes only local `status.json`. A subsequent aggregate-only rerun can therefore select the older favorable snapshot, ingest the intervening failed aggregate attempt as empty history, and report success from historical coverage. A temporary source/runtime validation failure, authentication failure or other terminal aggregation infrastructure failure can be retried into a favorable result. This violates the adopted terminal-failure policy even though the later attempt validates its own current inputs correctly.

   Bounded reproduction used the existing `SnapshotFixture`, with actual `fresh_inventory()`, `ingest()`, `checked_recovery()` and `runner.aggregate()` code. The fixture had valid 24/24 coverage through attempt 2. I added a completed, failed `mutation-fixture-aggregate` job to attempt 3's authenticated jobs response, without a snapshot, then aggregated at attempt 4 with no new workers. Only the later attempt's local current-source validation was mocked to its valid fixture context; API history, ingestion and model evaluation were not mocked away. The result was `{"state":"complete","reason":"exact_coverage","planned":24,"completed":24,"remaining":0,"failing":0}`. Stored phase inventories for attempts 3 and 4 were both empty. Changing that same prior job's name to `mutation-fixture-prepare` correctly rejected it with `started preparation failed; terminal infrastructure failure`.

   Repair the authenticated per-attempt phase inventory so a started historical aggregate cannot disappear. Accept a failed aggregate only when its authenticated retained verdict establishes an allowed incomplete state; preserve terminal verdicts, and fail closed when a failed aggregate lacks the required verdict evidence. Keep the current in-progress aggregate distinct from historical producers. Apply the invariant both during tail ingestion and when validating retained snapshots so the failure cannot be omitted in the next sealed frontier.

   Required negative controls: (a) complete historical coverage plus a failed aggregate without a snapshot must remain a terminal failure on the next aggregate-only rerun; (b) an explicit terminal aggregate verdict must remain terminal across a subsequent snapshot; (c) authenticated expected incomplete aggregation must still permit continuation; (d) an aggregate-only attempt with valid current inputs and no failed historical aggregate must still pass without new workers. Delete the new rejection guard in an isolated copy and require the named bad-input assertion to fail, while the valid control remains accepted. Existing `test_aggregate_requires_current_refresh_even_with_complete_predecessor` checks only the currently failing call, not whether the failure survives the following attempt.
