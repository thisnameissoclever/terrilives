## Proposed bounded API contract

Keep `verify_committed_contract(api, repository, revision, contract)` and every caller signature unchanged. Use only the existing authenticated repository API transport and its existing metadata cache. Do not add a fallback to a recursive query, a contents endpoint, another revision, a receipt's self-asserted hashes, or a fresh tool build.

1. Validate that `contract["files"]` and `contract["git_blobs"]` have exactly the fixed `CONTRACT_PATHS` keys before requesting metadata. Validate required hash shapes. Derive traversal paths from the constant, not caller-added paths. The current fixed set contains the workflow, patch, toolchain file and eight helpers.
2. Request `repos/{repository}/git/commits/{revision}`. Require the returned commit SHA to equal the exact requested revision, and require its root tree SHA to be a lowercase 40-digit hexadecimal object ID before interpolating that ID into a request path. Preserve the independent workflow/content authentication already performed by callers.
3. Request `repos/{repository}/git/trees/{root_sha}` with no `recursive` parameter. Require a mapping response, `sha == root_sha`, `truncated is False`, and a list of entries. A missing/true/nonboolean truncation field refuses the response. A request error propagates; no retry or alternate evidence path is introduced.
4. Validate every returned immediate entry name before indexing: it must be a nonempty string representing exactly one safe path component, with no slash, backslash, dot/dot-dot component, colon or NUL. Reject duplicate names before building a dictionary; do not silently overwrite a duplicate. Require selected object IDs to have the same strict SHA shape before interpolation. Other valid entries can exist, but they do not authorize traversal outside the fixed recipe ancestry.
5. Select `rust-toolchain.toml` from the root as a blob. Select `.github` as a directory only when its type is `tree` and mode is exactly `040000`. Request its SHA and require the returned tree header SHA to match that selected parent entry. This binds the child response to the authenticated commit ancestry.
6. From `.github`, authenticate the patch leaf and the `scripts` and `workflows` directory entries. Both selected directories require `tree`/`040000`. Fetch their nonrecursive trees by the parent-provided SHA, again requiring exact returned SHA, explicit nontruncation, safe immediate names and uniqueness.
7. For every fixed recipe leaf, require exactly one selected entry, type `blob`, mode `100644` or `100755`, and SHA equal to that exact path's committed `contract["git_blobs"]` value. A symlink, submodule, directory in place of a leaf, absent leaf, wrong mode, wrong hash or incorrect subtree header must refuse. Preserve the existing reviewed source SHA-256 contract and all independent producer, artifact, retention and runtime guards.
8. The complete successful traversal visits exactly these four parent paths: repository root, `.github`, `.github/scripts`, `.github/workflows`. It fetches no blob body and never descends into assets, docs, crates or any other tree. Four follows from the fixed path set, not a configurable limit. No archive/member/history/discovery/request/time limit needs to change. If a required immediate tree itself is truncated, authentication still fails.

GitHub remains the authenticated metadata authority, as it is today. Checking a returned tree object's SHA against the selected parent SHA strengthens the existing response binding; this proposal does not claim to recompute Git's tree-object hash from API JSON.

## Callers, fixtures and request accounting

1. Direct verification call sites are `mutation_tool.authenticate` (workflow and checkout commits), `mutation_qualification.verify` (both commits), `mutation_recovery.load` (both commits), and `mutation_native.authenticate` (both commits). `mutation_workflow.bind_tool`, planning, qualification discovery, native stages, preparation and snapshot consumers reach these methods indirectly. `consume_prepared` authenticates retained executable bytes without independently calling the tree verifier; snapshot loading still calls it first.
2. `WorkflowAPI` inherits `CachedMetadata`. Each distinct metadata path charges one request, then subsequent equal paths reuse the response. `RecordingAPI.json` forwards to that wrapper without another cache or charge. Nonrecursive tree responses keyed by exact SHA naturally reuse shared parents across workflow/checkout revisions and across authentications within the same job. No new cache is needed.
3. One uncached verifier invocation changes from one commit plus one recursive tree request to one commit plus four nonrecursive tree requests: 2 becomes 5, an increase of 3. Two different revisions with different root and parent trees can cost 10 rather than 4, an increase of 6. If revisions share parent trees, the wrapper cache reduces this cost. For R distinct authenticated root trees in a single wrapper, the increase is at most 3R; shared subtree SHAs can reduce it. Do not assume every production revision shares the same root simply because the recipe files match.
4. Existing fixture `ToolAuthenticationTests.setUp` supplies both commit revisions `b*40` and `e*40` with one common `c*40` root, so current wrapper fixtures should gain three charged requests per job. This is a code-derived projection, not a measured post-change result. Direct uncached FixtureAPI calls can request the four trees twice; those call counts must be distinguished from WorkflowAPI's HTTP demand.

## Minimal implementation ownership and verification

1. Production owner: `.github/scripts/mutation_tool.py` only. Replace the verifier's recursive metadata query with a small fixed-ancestry traversal and validation. Preserve the public signature and every other tool/qualification/native/recovery interface. No workflow or authentication adapter change is needed.
2. Primary tests: `.github/scripts/test_mutation_tool.py`. Replace the central flat recursive fixture with four explicit nonrecursive parent tree responses, each carrying its own SHA and proper tree/leaf rows. All qualification, recovery, native and workflow fixtures inherit this setup. Update the existing altered-helper test to mutate the scripts-tree leaf. Update its existing isolated blob-guard removal control if the exact source expression changes; keep its intended ordinary assertion failure.
3. Narrow additional ownership, if needed: `.github/scripts/test_mutation_native.py`, only for the proven request-accounting literals and their measured bounds. Use fresh full-wrapper outputs to establish worker, padded aggregate and native-stage maxima. Keep the 800/850/400 limits and 56-history test assumptions unchanged. No edit to production mutation_native.py or mutation_recovery.py is justified by this investigation.
4. Positive tests should prove all 11 exact leaves authenticate; unrelated large subtrees are never fetched; no request uses `recursive=1` or downloads file bodies; two commits sharing root/parents use the existing cache; distinct workflow/checkout roots still bind independently with correctly counted requests. Include an explicit truncated recursive fixture that cannot be used as a successful shortcut, while valid immediate-tree evidence succeeds.
5. Negative tests should independently alter commit SHA, root/header SHA, child/header SHA, selected subtree SHA, tree mode/type, leaf mode/type/SHA, required file sets and hash shapes; delete a directory or file; duplicate an immediate name; insert unsafe immediate names; and set truncation true or omit it at each required level. Wrong parent SHA must refuse rather than following an attacker-chosen alternative. API failures must refuse without falling back to recursive or contents evidence. Assert refusal before any executable restoration or execution where using full authentication.
6. Isolated controls should remove the subtree-header binding, duplicate rejection, selected directory guard, and final blob binding in separate temporary copies. Each corresponding negative test must fail at its intended assertion, with a passing unchanged control and no import/syntax error. Production source must remain byte-identical throughout controls.
7. Run focused tool authentication, qualification authentication, recovery/native consumer contracts and the four request-budget tests named above after the patch. This is concern-driven verification for the changed recipe authentication path, not reopening closed model, executor, native admission or batch-budget design reviews. Root owns exact hashes, scoped review, lessons, Git delivery and the fresh recipe fixture. Existing Rust/web outcomes stay separate.
