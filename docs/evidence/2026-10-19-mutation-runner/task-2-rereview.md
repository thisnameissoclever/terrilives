## Remaining finding

1. **P2: A legitimate partial source write aborts the campaign as permanent input drift.** `.github/scripts/mutation_runner.py:493-501` defers an input-check failure only when `outcomes.json` also changed. The active mutation's source file can change independently while that report remains stable. The pinned tool's `BuildDir::overwrite_file()` calls non-atomic `std::fs::write`, which truncates then writes the file. `apply()` runs before the scenario's build/test, and `revert()` runs before the next outcome is published. Therefore an empty or partial active source read is a valid observation during those transitions. The new `OwnedInputs.verify()` reports a byte mismatch, and the controller immediately terminates the invocation and discards its checkpoint. See the pinned [overwrite implementation](https://github.com/sourcefrog/cargo-mutants/blob/8ab1dc786a1f61a4e370416cc6c68b81a704e917/src/build_dir.rs#L86-L105) and [scenario ordering](https://github.com/sourcefrog/cargo-mutants/blob/8ab1dc786a1f61a4e370416cc6c68b81a704e917/src/lab.rs#L271-L321).

   A deterministic bounded reproduction used the existing `RunnerTests.owned_input_fixture()` and real owned child-process controller. The child published a valid baseline-only report, opened the first pending mutation file with `wb`, and paused after truncation. The input observer read that empty file, then released the child to write the exact approved `mutation_bytes()` result. The task-owned process wrapper waited for that write to finish before normal shutdown. The report bytes never changed. The controller returned `infrastructure_failure`, reason `invalid_report: owned input bytes changed: crates/terri-core/src/appearance.rs`, with no snapshot. Both `final_bytes_are_exact_expected_mutation` and `report_remained_unchanged` were `True`. No Rust code or modified tool was executed. The scheduling handshake exposes a real filesystem interleaving; it does not introduce an unexpected final input change.

   Distinguish a transient observation of the currently allowed active file from stable unexpected changes. While the process is running, defer acceptance when that file may be between its permitted byte states; retain the earlier validated snapshot and never import the partially observed bytes. Keep unrelated path, mode, link, lockfile and source changes failing. At the final stopped-process boundary, require exact permitted input bytes and reject invalid final state. Do not reset unexpected changes and then accept the results produced before that reset. Add deterministic apply and revert transition fixtures, plus controls proving stable unexpected drift and invalid final input still fail. A slower polling interval or removal of the byte check would not repair the boundary.
