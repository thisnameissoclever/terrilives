# Native campaign capacity architecture review

## Real goal

[G1] Finish every identity in the immutable native mutation manifest through authenticated, resumable work under the existing eight global slots, job windows, evidence limits and finite campaign stops. A successful bounded invocation is progress; only exact aggregate coverage with passing policy establishes campaign success.

## Diagnosis check

[D1] The raw member estimator confuses different storage units. `mutation_native.py:492-495` multiplies the largest diagnostic file by every identity in the largest slot, then treats that sum as one archive member. `mutation_runner.py:637-651` actually stores the raw outcomes report as one member and each referenced scenario log/diff as separate members. `mutation_artifacts.py:48-69` separately limits compressed archive bytes, each member, expanded total and member count. The current multiplication cannot represent all these limits correctly.

[D2] The independent reproduction establishes false refusal without assuming future native behavior. I read `task-3-native-admission-raw-sizing-preflight.md`: its 800-identity synthetic manifest and complete 100-record slot produced 205 members, an 813,926-byte largest member, 31,298,522 expanded bytes and 174,937 ZIP bytes. The actual unpacker and bundle validator accepted it. The estimator rejected the same 300,000-byte log shape by projecting a 30,000,000-byte member and 120,000,000-byte archive subtotal. These are supplied synthetic results, not my execution or native/Linux measurements. The repeated-text compression result is not a prediction of native compression.

[D3] Correcting file classes alone does not establish a smaller execution envelope. `mutation_runner.py:769-812` selects all remaining identities and launches one warm invocation. `run_controller` has a deadline and a fixture-only record stop at lines 489-550. Fixed maximum phase durations establish no minimum duration, so fast mutations can exhaust the entire selection. Substituting sampled records per wave for slot cardinality would be unsound while this selection remains unrestricted.

[D4] A bounded prefix needs explicit incomplete status after normal tool exit. `run_controller` returns `complete` for a normally completed selection at `mutation_runner.py:587-589`. `execute_slot` changes that state for policy failure or exact slot completion at lines 815-824, but has no branch for successful selected work with remaining slot identities. Introducing a prefix without repairing this branch would upload a false successful worker verdict. The aggregate would still reject missing coverage, but retained producer/job semantics would already be wrong.

[D5] Existing recovery supports bounded deltas. Exact selection is validated against `batch_ids` in `mutation_campaign.py:283-292`; the raw report is reconstructed using the same batch in `mutation_artifacts.py:237-248`; recovery merges retained deltas in `mutation_recovery.py:369-379`. No second executor or second result model is required. Recovery removes the repeated manifest from retained bundles at `mutation_recovery.py:520-521`; it retains every other bundle field, producer proof and started-stage inventory.

[D6] The first two capacity findings were real but at different layers. `native-plan-size-probe.json` records 18,543 identities and a pretty-plan lower bound of 34,234,770 bytes against a 33,554,432-byte member cap; its compact lower bound is 22,720,322 bytes. These are lower bounds, not a complete plan size. `mutation_native.py:44-57` now preserves complete values while compacting transport. The separate capped forecast at lines 390-410 now includes repeated capped baselines, setup, reserves and queue allowance. Neither repair provides a production batch boundary, so another scalar adjustment cannot finish the architecture.

[D7] Exact reader and snapshot guards exist, but the outgoing worker path is incomplete as a capacity boundary. The workflow's `finally` block only compacts/checks `bundle.json` before enabling upload (`mutation_workflow.py:485-489`). `retain_bundle` and the copies at `mutation_runner.py:825-829` do not enforce the complete outgoing member/expanded/count budget. Recovery will reject an oversized archive later. The repair should fail explicitly before publishing an unusable successful result, retaining that capacity failure in started-stage history.

## What was taken as fixed but is not

[F1] A logical slot need not equal one tool selection. The approved plan's proposed repair explicitly calls for bounded batches. Eight immutable slot assignments and complete final coverage can remain fixed while each invocation receives a deterministic prefix of that slot's remaining order.

[F2] A record-count limit need not be implemented as another controller kill condition. Selecting at most B identities before launch establishes the count bound directly. It allows normal completion and preserves the existing pre-signal rules for actual deadline interruption. The fixture stop remains fixture-only.

[F3] Timing and artifact capacity need not share one estimate. The admitted count can be constrained by transport size, while expected throughput is separately constrained by measured time. Future log volume remains an assumption. A source-bound algorithm, authenticated admitted count and exact runtime byte checks make that distinction enforceable.

[F4] A smaller batch does not make accumulated history smaller in every dimension. It reduces each `delta.batch_ids`, but adds repeated baselines, producer logs and metadata across more attempts. `status.remaining` still contains the whole remaining slot (`mutation_runner.py:653-654`). The snapshot retains that status and complete records. The current synthetic history shape at `mutation_native.py:466-470` is not the actual retained schema and cannot silently be reinterpreted as a complete hard bound.

## Alternative routes

[ALT1] Admit and execute a deterministic bounded prefix using the existing executor.

Mechanism: compute a maximum selection count B from typed artifact projections, freeze it in authenticated native admission, and select `ordered_remaining(... )[:B]` before constructing the selection, provenance digest and source guard. Keep the original full manifest, assignments and outcome validator. After successful prefix completion, report incomplete progress unless exact slot coverage is complete.

Work required: add the compatible execution seam, typed sizing and exact outgoing validation; bind the admitted policy through preparation/recovery; update forecast/history sizing and focused tests. Detailed interfaces and checks are below.

Costs and risks: every bounded invocation repeats baseline/setup. Small B can make the campaign infeasible within its original lifetime or history allowance. Unexpected individual output growth can still cause terminal capacity failure. No sample can guarantee arbitrary future log sizes.

Makes easier or harder later: exact prefix selection gives a simple reusable execution bound, unchanged identity validation and truthful resume behavior. It sacrifices some warm-invocation throughput when capacity forces an early boundary, but introduces no additional producer protocol or scheduler.

[ALT2] Add a producer-owned permission boundary before every next mutation.

Mechanism: extend the pinned tool patch so the producer requests or checks admission after closing each completed scenario and before modifying source for the next one. The controller can then inspect actual closed reports/logs and reserve capacity for the next scenario without racing a poll against a new mutation. The producer emits a distinct controlled-incomplete result at refusal.

Work required: change the approved tool patch and its receipt identity, add the protocol and source-restoration tests, rebuild and requalify the tool, and adapt the same raw report validator/controller. A next-record byte reservation still needs a declared bound or terminal failure when one scenario exceeds it.

Costs and risks: this crosses the Rust tool/Python controller boundary and expands the existing tool patch. It requires stronger crash, lost-message and restoration proof. It cannot guarantee a future log is bounded unless writes themselves are bounded, which would introduce another explicit failure path rather than permission to truncate evidence.

Makes easier or harder later: actual byte-based stopping can retain longer warm invocations and reduce repeated baselines. Protocol maintenance and tool upgrades become harder. This is a legitimate long-term producer design, but exceeds the smallest repair and requires renewed review of the existing patch contract.

## Recommendation

[R1] Choose [ALT1], the authenticated bounded-prefix route. The defect is the missing relationship between a logical slot, one executable selection and one retained artifact. A deterministic prefix establishes that relationship without modifying the already reviewed interruption mechanism or inventing another executor. Correct file-class sizing at the same time; neither change alone is sufficient. This is within the approved bounded-batch objective, subject to the root's scoped implementation review. I am not authorizing source edits or treating this recommendation as native admission.

[R2] Add one optional keyword-only execution seam to `mutation_runner.execute_slot`, with no caller-controlled workflow/CLI batch flag. The production workflow must obtain the batch policy only after `native.validate_admitted(data, settings)` in `mutation_workflow.execute` (`:347-369`). Existing fixture callers can keep their current behavior. Production manifests under the new recipe must reject missing or mismatched admitted policy. Impact-scan every caller before selecting the exact signature. Apply B before `batch_config`, selection enumeration, `OwnedInputs.configure`, provenance `batch_id` and `run_controller`; all must receive the same prefix. Keep the current source/executable checks before execution and the protected-checkout check afterward.

[R3] Freeze the algorithm/version in the committed recipe before planning, and freeze its computed B in authenticated pilot/report/admission evidence. Do not edit the original plan after measurement. `collect_context` already fingerprints runner/workflow inputs (`mutation_runner.py:357-371`), and `mutation_tool.CONTRACT_PATHS` includes all relevant helpers (`:30-34`). Carry the exact policy/digest through `admission_decision`, `install_admission`, `validate_admitted` and `load_admission` (`mutation_native.py:704-813`). Require equality on normal preparation, snapshot recovery, workers, complete-history shortcuts and aggregate-only paths. Reject extra caller JSON intended to change B, byte assumptions or the history ceiling. Requalify the changed committed recipe before production measurement/admission; prior qualifications are not transferable.

[R4] Replace the scalar raw estimator with a typed inventory. For a candidate B, calculate the complete compact bundle, frozen raw outcomes, baseline log once, each mutant log/diff, process stdout and post-shutdown diagnostic outcomes separately. Use maximum individual size for the member test and the sum for expanded size. Model aggregate report/stdout growth separately from individual log growth. Count the actual generated members, including fixed members and baseline references; deduplicate shared paths exactly as the writer does. Do not assume four equal members per mutation. Include raw report serialization rather than sizing it as compact application JSON. Preserve the current twenty-percent projected headroom and every unchanged hard cap.

[R5] Compute B using the real full manifest and per-identity serialized shapes, with measured variable-field/log assumptions clearly named. Evaluate the worst applicable future prefix in every slot, not only the first prefix or the slot with most identities. A shorter slot can contain longer names, paths or replacement values. One simple conservative calculation uses the largest relevant row costs across the full manifest for B records; a precise prefix calculation is also possible if it covers all allowed resumed positions. Prefer the largest B fitting the typed raw/member/count envelope, then check the resulting history/time envelope. If even one identity cannot fit, refuse. Never lower B until a time/history failure appears favorable, because smaller batches add repeated costs.

[R6] Recompute both time forecasts using the enforced count. Expected throughput is `min(B, floor(usable / measured_unit))`; capped throughput is `min(B, floor(usable / capped_unit))`. Derive waves, repeated costs and the admitted total-history ceiling from that throughput. Include already consumed planning/measurement/review attempts. Preserve seven days, at most eight runs, at most 51 attempts per run, existing no-progress stops, the fixed 120-minute jobs and original caps. A separate total-history ceiling must be no larger than the original stops and must fit the original remaining lifetime. Reject if the joint raw/history/time envelope cannot fit; a larger B or extra runs cannot be invented after admission.

[R7] Size the actual retained schema through the existing `encode`/`decode` implementation, with distinct labels for exact bytes and sample-shaped projections. Keep one full manifest, all final record fields including their repeated baseline/provenance data (`mutation_campaign.py:404-409`), each delta's at-most-B `batch_ids`, every retained full-slot `status.remaining`, baseline/delta references, original artifact metadata, worker and phase inventories, aggregate verdicts, native proofs, and exact retained producer-log representations. Budget full-slot remaining arrays at every admitted attempt unless a separately proved tighter count covers interrupted/no-progress attempts too. Smaller `batch_ids` must not accidentally remove another retained copy of IDs. Producer logs include base64 expansion. Preserve the logical reconstruction guard even when interned or ZIP bytes are tiny (`mutation_recovery.py:114-183`).

[R8] Enforce actual output capacity before enabling worker upload, using one shared path/size inventory checker consistent with `artifacts.unpack`. Check every retained regular file, member count, per-member and expanded sum after final retention; validate the resulting archive with the existing reader on consumption. Compressed artifact bytes still need the existing actual uploaded metadata/download check because the uploader creates the final ZIP. Do not claim the local expanded sum proves the final compressed limit. If exact bytes exceed a bound, fail as capacity and retain the failed started-stage evidence; never drop a log, shorten a report, accept only favorable records or retry that failure into success. This provides a hard accepted-artifact bound, not a hard upper bound on temporary producer disk writes. Polling file sizes cannot prove the latter.

[R9] Keep controller cleanup intact. Normal bounded-prefix completion needs no new signal. A real deadline still freezes the last validated pre-signal bytes, reaps the complete owned process group and ignores post-signal result claims. The active identity stays first in the next remaining prefix because only valid terminal records are removed. After merging, policy failure takes precedence, exact slot coverage alone permits worker completion, and otherwise a nonempty valid delta is incomplete progress. Real timeouts, counted survivor failures, source drift, malformed evidence and cleanup failure remain terminal. Aggregate exact equality is unchanged.

[R10] Add meaningful acceptance tests and isolated guard-removal controls:

1. A slot larger than B finishes its first exact prefix normally, uploads incomplete progress, resumes at the next identity, and reaches exact final coverage across batches. No identity is skipped or terminally executed twice. Restore the old complete-state fallthrough and require the intended status assertion to fail.
2. A fast fixture tries to finish its whole provided selection before any deadline. Assert it was provided only B identities. Remove prefix selection and require cardinality/selection assertions to fail. Do not use timer luck as proof of a count bound.
3. Interrupt inside a prefix after a valid terminal record; emit a fake caught result after termination; require the existing pre-signal exclusion and active-identity-first resume. Keep cleanup failure, owned-source drift and real timeout controls.
4. Reproduce the supplied separate-log artifact acceptance and old scalar false refusal. Independently exceed one member, aggregate expanded bytes and member count while all other bounds fit. Test process-output and raw-outcomes growth separately, plus a longer-row smaller slot. Exercise the actual outgoing checker and actual reader.
5. Build synthetic history in the real retained schema with several bounded deltas, full `status.remaining`, distinct producer logs, interrupted/no-progress attempts and complete records. Round-trip exactly through encode/decode. Exceed logical reconstruction while compressed/interned bytes remain small. Removing the logical guard must fail the named assertion.
6. Tamper B or its policy digest in admitted proof, prepared data, a sealed snapshot and aggregate-only complete history. Preserve all other valid evidence so each test reaches the new binding boundary. Reject a batch outside the frozen prefix/envelope and an old qualification after recipe change. Preserve valid same-run targeted admission and continuation controls.
7. Show a byte-limited B increasing required waves and changing a previously favorable finite-envelope verdict to refusal. Cover exact boundaries, one-identity nonfit, zero capped throughput, original history-ceiling exhaustion and original lifetime exhaustion.
