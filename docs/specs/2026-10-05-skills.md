# Skills: one number per person per craft, learned by doing

Status: implemented on 2026-10-05; the evidence is in [the skills verification record](2026-10-05-skills-verification.md). This is the implementation contract for the first playable slice of [S-skills] in `docs/GAME-SYSTEMS.md`, written on 2026-10-05 against main `845101d8` during autonomous roadmap work. Consequences beyond fumbling (better outcomes, unlocks, career performance) are later slices; this document leaves the data in place for them.

## [SK-model] A skill is practice on a ladder

A skill is defined in content (`content/skills.toml`): an id, a label, a one-sentence description, the activity tag it keys on (the same tag space traits and hobbies use), the number of levels on its ladder, and how much practice one completed attempt adds. Every person holds, for each skill, one number: practice, from zero up to the practice the top level costs. Level and progress are derived from practice through one tunable ladder: level 1 costs `skill_level_cost` practice, and each level after it costs `skill_level_growth` times the one before. Mastery is the fraction of the ladder climbed, `(level + progress within the current level) / levels`, from 0 to 1.

Practice is held in a sparse per-person component sorted by pack skill index, saved by authored id in an appended save-envelope field, and hashed in a sparse tagged block. A person with no row for a skill is at level 0 with no progress.

## [SK-learning] Every completed tagged attempt teaches everyone

When an interaction, a chain step or a social interaction with tags completes, every participant's practice rises by the skill's `practice_per_attempt` for every skill whose tag the activity carries, pass or fail, clamped at the top of the ladder. Interrupted attempts teach nothing, as capabilities already behave. Learning no longer lives on the capability trait: `learn_per_attempt` leaves the trait schema and content, and the capability kind keeps only `start_level` and `fail_delta_scale`.

## [SK-capability] The capability trait becomes a handicap on its skill

A capability trait keeps its meaning as the thing that makes an attempt fallible: a person wearing "Can't cook" may fumble a tagged attempt, a person without it never rolls. What changes is where the level comes from. The fumble roll reads the mastery of the skill whose tag matches the trait; the trait's own saved state is no longer read or raised by play. If no skill carries the trait's tag, the roll keeps reading the trait state so content without a matching skill still works.

Wearing a capability trait never lowers a skill. When a person spawns with one, or gains one through Edit Sims, their practice becomes at least the practice that reproduces the trait's `start_level` as mastery. Removing the trait leaves the skill where it is; the person simply stops fumbling. The Edit housemate note changes accordingly: a removed condition forgets its severity, and skills are kept.

## [SK-save] An appended optional field, with a one-time seed

The envelope gains `skills: Option<SavedSkills>` after `dining`. `SavedSkills` holds rows of `(entity index, skill id, practice)`, ascending by entity index then id, each referring to a living person, a known skill id, and a finite practice within the ladder. A missing whole field (every save written before this slice) restores as `None`, and the loader then seeds practice once from each worn capability trait's saved state through the inverse ladder, so nobody loses the competence they already had. A present field, even an empty one, is authoritative and seeds nothing. An unknown skill id in a present field is a content mismatch and refuses the load, as an unknown trait id does. Skill ids are not part of the content fingerprint: saved practice cannot be reinterpreted by adding a skill.

The padded decoder, the historical-prefix tests and the frozen local-bed order all extend by one field, as the chronotype field did. Loading applies no learning and advances no tick.

## [SK-hud] Where the player reads it

The Traits panel keeps its "Skill {n}%" row on a capability trait, now showing the matching skill's mastery. The Overview sheet gains a collapsed "Skills" disclosure beside "Personality, habits and bed" that lists every content skill for the selected person: the skill's label, a standing line "Level {n} of {levels}, {p}% to the next level", and the skill's description. The percent is floored, so it never reads 100% before the level changes; at the top of the ladder the standing line reads "Level {levels} of {levels}". Functional text stays plain. For a capability trait, the debug overlay prints the matching skill's mastery, the same value the Traits panel shows; for the other kinds it prints the trait state.

## [SK-content] The first three skills

`cooking` ("Cooking", tag `cooking`), `exercise` ("Fitness", tag `exercise`) and `reading` ("Reading", tag `reading`), ten levels each, with practice per attempt chosen so the shipped capability learning pace is kept near level 1: the first level costs the same practice the old trait gained in about seven attempts. Numbers are in content and tuning, never in code.

## [SK-evidence] Proof required before delivery

1. The ladder: level and progress for practice at every level boundary and between, the inverse ladder reproducing a mastery, and clamping at the top; one f32 step of practice below a boundary stays on the lower level.
2. Learning: a completed tagged interaction, chain step and social interaction each add exactly one attempt's practice to each participant, interrupted attempts add nothing, an untagged completion adds nothing, and a person without the trait learns at the same rate as one wearing it.
3. The roll: a wearer's fumble chance follows skill mastery, not the trait state; a non-wearer never draws; PRNG consumption is unchanged for a given world; a tag with no skill falls back to the trait state.
4. Seeding: spawn and Edit Sims raise practice to the trait's start level and never lower it; removing the trait keeps the skill.
5. Save: a current save round-trips rows exactly, an older save without the field seeds once and then saves the field, an empty present field seeds nothing, invalid rows (unknown id, disorder, duplicate, non-person, out of range, non-finite) refuse the whole load without touching the live world, every historical truncation refuses, and the world hash observes practice and its owner (change one, hash changes; restore, hash restores).
6. The Overview disclosure and the Traits panel in a displayed browser at desktop and phone widths, with screenshots, and no change to save bytes from reading.
7. Guard deletions recorded with the failing assertion and byte restoration for the ladder boundary, the clamp, the seed, the fallback, the ordering validation and each hash input.
