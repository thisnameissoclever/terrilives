# Windows: a wall line that stops people and passes daylight

[B-windows] in `FEATURES.md`, named in [S-build] in `GAME-SYSTEMS.md`. The house already has walls and doorways, and since [OS-daylight] the sky reaches indoors through doorways and stops at walls, so a closed back room is dimmer than the yard at noon. A window is the third thing a wall line can be: nobody walks through it, and the sky does.

The original placement slice shipped in PR 126. The 2026-10-01 implementation adds nine window models, a nested Windows chooser and whole-span edits. The current local delivery and review status is recorded in `docs/assets/review-evidence/architecture/verification.md`. The historical wire-format description below remains relevant to old saves.

## [WN-state] Historical single-line storage

The original window slice appended `Window` code 3 after `Open` 0, `Wall` 1 and `Doorway` 2. Historical `SimCommand::SetWallEdge` records retain their original shape and code meanings.

It appended `SavedLayout::EdgeWallsV2 { edges, windows }` after `LegacyAuthoredV1`, `LegacyCells` and `EdgeWallsV1`. Its `windows` field stores `Vec<WallLine>`. A line cannot appear in both the window and wall lists; loading rejects overlap and duplicate records. No field was inserted into an existing postcard record, whose positional encoding cannot tolerate that change.

Current whole-window edits use `EdgeWallsV3 { edges, windows }`, where windows are typed model/start descriptors. The typed constructor retains V3 even when its final window is removed so unrelated edits preserve storage identity. Historical layout variants and command records remain readable.

## [WN-old-saves] Preserve historical layouts and commands

`EdgeWallsV1` has no windows. The original single-line format used `EdgeWallsV2`; its lines decode as one-unit Sash placements through `window_placements()`. `window_lines()` expands current descriptors for historical consumers, and `window_at()` resolves any covered line to its complete owner. Old `edges()` and `windows()` accessors remain available for their original callers.

The current writer never inserts fields into old records. New descriptor layouts and Fit/Remove command variants append after existing variants. Older game versions cannot be expected to decode newer variants. Whole-span bounds, overlap and straight-wall validation apply when loading current descriptors, including commands saved before execution.

## [WN-rules] What a window does

- **People.** A window blocks movement exactly as a wall does. Pathfinding reads the same blocked set, so nothing in the mover changes.
- **Daylight.** The sky flood in `web/src/render/sky.ts` steps through a window as it steps through a doorway, losing the same `daylight_reach_per_tile` per tile.
- **Lamp light.** A window blocks a lamp's pool, as a wall does. A pool that leaked through the glass would light the yard from the living room lamp, which is not what the indoor pools are for, and there is no outdoor lighting yet.
- **Reach from the door.** A window is not a way in, so the front-door reach rule ([RD-reach]) treats it as a wall.
- **Sound and conversation** are unaffected: neither reads wall state today.

## [WN-art] Authored windows and matching walls

Nine models have physical openings, frames and glazing on both wall axes. Sash, Cottage and Arched span one wall unit; Sliding, Steel-grid and Twin casement span two; Picture, Craftsman and Clerestory span three. Their full and cut forms share the wall thickness, reveals and baseboards. Rear exterior openings remain full height in play; interior and front openings follow their owning cutaway wall.

## [WN-tool] Choosing a model in Build

Open Build, choose Walls, then Windows. N opens this chooser from any Build tool. Select a model and a wall line, then use Fit window. An existing window changes that action to Replace window and also exposes Remove window. Choosing any covered line selects the whole existing window. Replacement starts at that window's canonical first line; removal clears its entire span. The selected model is retained when leaving and reopening the chooser.

Fit requires a straight supported wall span. Junctions, partial overlaps and edits that break access are refused before application. Other wall and Room edits cannot leave a fragment of a wide window. The status reports the simulation's applied result, including refusals, rather than treating a queued command as success. Rear-shell lines can be selected from inside the lot without moving outdoors.

## Whole-window storage

`WindowModel` and `WindowPlacement` give each opening one model and one canonical start. Appended layout variants store these descriptors; historical window-line saves become one-unit Sash placements. New Fit and Remove command variants append after historical commands. Save/load rejects overflowing, overlapping or unsupported spans. Content ordering and historical atlas records remain unchanged.
