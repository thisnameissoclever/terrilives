# Windows: a wall line that stops people and passes daylight

[B-windows] in `FEATURES.md`, named in [S-build] in `GAME-SYSTEMS.md`. The house already has walls and doorways, and since [OS-daylight] the sky reaches indoors through doorways and stops at walls, so a closed back room is dimmer than the yard at noon. A window is the third thing a wall line can be: nobody walks through it, and the sky does.

This is one slice. A player opens Build, picks Walls, picks Window, clicks a line of the house, and the room behind it brightens. The window is saved and reloads.

## [WN-state] A third wall state, appended

`WallState` gains `Window` with code 3, after `Open` 0, `Wall` 1 and `Doorway` 2. The order is the wire order, and the enum's own comment already says append only, so nothing existing moves. `SimCommand::SetWallEdge` carries the code it already carried, so the command wire format does not change shape; a save or a command holding 0, 1 or 2 means exactly what it meant before.

The saved record does not gain a field. `WallEdge` is written by postcard, which lays a struct's fields back to back with no framing, so adding a field inside a record that repeats would move every byte after the first one and no old save would load. The layout is an enum instead, and an enum grows by appending a variant: `SavedLayout` gains `EdgeWallsV2 { edges, windows }` after `LegacyAuthoredV1`, `LegacyCells` and `EdgeWallsV1`. Postcard writes the variant's index, so every existing save still says `EdgeWallsV1` and still decodes as it always did.

`windows` is a `Vec<WallLine>`: a line in it is a window, a line in `edges` is a wall or a doorway as before, and a line must not be in both. The writer removes a line from one list when it puts it in the other, so the game cannot produce one. A save that holds a line in both is corrupt, and the loader refuses the whole save rather than choosing for it, which is what it already does for a repeated wall record. Where something has to name a state anyway, off the loading path, the wall wins: a barrier kept by mistake is safe and one dropped by mistake strands a sim outdoors.

## [WN-old-saves] Every existing save still loads

An old save holds `EdgeWallsV1` and is read as a house with no windows. Nothing is padded and no byte moves, which is what choosing the enum over a new field in the snapshot bought. A save written now holds `EdgeWallsV2`, and older code would refuse it, which is the same one-way street every earlier save growth here has had.

Call sites stop matching the variant by name. `SavedLayout` gains `edges()` and `windows()`, so the dozen places that read the architecture ask for what they need rather than naming a version, and the next variant costs one method rather than a dozen matches.

## [WN-rules] What a window does

- **People.** A window blocks movement exactly as a wall does. Pathfinding reads the same blocked set, so nothing in the mover changes.
- **Daylight.** The sky flood in `web/src/render/sky.ts` steps through a window as it steps through a doorway, losing the same `daylight_reach_per_tile` per tile.
- **Lamp light.** A window blocks a lamp's pool, as a wall does. A pool that leaked through the glass would light the yard from the living room lamp, which is not what the indoor pools are for, and there is no outdoor lighting yet.
- **Reach from the door.** A window is not a way in, so the front-door reach rule ([RD-reach]) treats it as a wall.
- **Sound and conversation** are unaffected: neither reads wall state today.

## [WN-art] Drawn with the wall art it has, for now

There is no window art. The mechanism ships drawing a window as the wall panel it stands in, in a lighter colourway, so a player can see which lines are windows and where the light comes from. The need is logged in `docs/TIM-TODO.md` as [T-window-art]: a wall panel with a glazed opening, for both the vertical and the horizontal line, matching the wall art that exists.

## [WN-tool] Choosing Window in the Walls tool

The Walls tool's dock gains Window beside Wall and Doorway, and N fits one from the keyboard. Every button offers a state the line is not already in, as Wall and Doorway do: on a glazed line, Window is disabled and Remove takes the window away. The cut-away rule from [WB-draw] is unchanged: while a wall tool is active every wall is drawn, windows included, and outside Build a window on a cut-away line is hidden with the wall it stands in.

## Slices

This is the whole of [B-windows] except the art, which is [T-window-art] and waits on the owner. Sims looking out of a window is a separate future item and is not part of this: it needs an interaction, an animation and a reason to do it, and none of those exist yet.
