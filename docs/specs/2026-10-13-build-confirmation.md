# Build confirmation and cancellation

Build mode treats the paused simulation as a draft. Existing furniture, wall, window, room, floor, and store actions update that draft. Place accepts an individual furniture preview into the draft. Switching selections or tools never makes a draft permanent.

The bottom of the build flyout contains Cancel followed by Confirm. Confirm settles queued edits and any pending furniture placement, records a new baseline, and then leaves Build mode. Cancel restores the most recent baseline and then leaves Build mode. A refused Confirm or a failed rollback keeps Build mode open, and the status line says why. Confirming one batch and cancelling the next keeps the first batch.

Every other way out reaches the furniture builder's exit, whose guard is `BuildExit.gate` in `web/src/ui/build-exit.ts`: Exit build, the Build button, and Escape with nothing selected. With nothing pending, Build mode closes at once. While changes are not confirmed, a modal dialog, Leave Build mode?, opens instead. Keep building has focus when it opens and is also what Escape chooses, wherever focus is on the page, without touching the build behind the dialog; Build mode stays open and focus returns to the control that asked to leave, or to the game view. Confirm changes confirms and leaves, staying open with the reason when Confirm is refused. Discard changes restores the baseline and leaves. Changes are pending when the draft's save bytes differ from the baseline, a furniture move is shown but not placed, or a build or book command is still on its way.

Escape first clears the current tool's selection and only tries to leave when nothing is selected. A held Escape counts once: its repeats do nothing, wherever focus is, so a dialog opened by a held key stays open until a fresh press. The contextual Cancel beside a selection clears that selection the same way, never leaves Build mode, and keeps every other pending change. Only the footer's Cancel and the dialog's Discard changes discard the batch. When Confirm is refused while a furniture move is shown, the status line asks the player to move it somewhere it fits or choose Cancel beside it.

A discard resets every tool as a Load does, so a purchase dropped with the draft cannot leave a tool waiting for its result. When a pointer click closes the dialog or leaves Build mode, by any route including Exit build with nothing pending, the clicks that continue that click's run are ignored outside an open dialog for up to a second, so the second click of a double-click does not reach the game. The browser's click count decides what continues a run: a double-click's second click counts 2, and Chromium counts a quick second tap at the same place the same way. A separate click starts again at 1 and goes through, and a close from the keyboard ignores nothing. When the graphics device is lost, the dialog closes as Keep building so the recovery message and Retry graphics are not hidden behind it.

`BuildSession` owns the baseline through the existing simulation save and validated-load APIs. All persistence paths use its committed snapshot, including manual Save, autosave, update, and graphics-device recovery. Successful Load replaces the baseline with the loaded household. Rejected Load preserves it. A failed rollback keeps Build open and paused, reports the failure, and retains the baseline.

Cancellation clears queued draft commands and tool receipts, restores funds and owned objects, and refreshes architecture, floor resources, selection, lighting, and audio. Store purchases, sales, and book transactions made during Build belong to the same batch. Household editing, chores, death settings, and Sim-detail controls are unavailable while the batch is active so cancellation cannot silently undo unrelated changes.

Physical room outlines include the owned lot perimeter. Perimeter solids are saved, drawn, and validated as physical architecture. They do not become movement-grid barriers between an owned tile and an out-of-bounds tile: off-lot movement is already disallowed. Doorways remain interior-only. The Wall tool can remove and rebuild explicit perimeter solids while preserving the original implicit rear shell. The original implicit rear house shell is not duplicated. Existing saves are preserved without guessing where old incomplete rooms were meant to have walls.

The window action is Place Window, and contextual cancellation controls read Cancel. Functional labels describe the action without humor.

Verification covers committed versus draft save bytes, cancellation before and after command draining, chained edits, confirmed-batch retention, rejected rollback, successful and rejected Load, perimeter geometry, and save round trips. Browser checks cover desktop and compact controls, including the button order and Exit behavior. Unit checks with a fake page cover the footer leaving after Confirm and Cancel, each dialog answer, Escape, focus, leaving with nothing pending, a refused Confirm or failed rollback keeping Build mode, the contextual Cancel keeping the batch, a purchase on its way, double-clicks, and closing the dialog for graphics recovery.
