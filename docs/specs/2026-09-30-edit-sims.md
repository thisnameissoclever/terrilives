# Edit Sims: preserve the person while changing their settings

This document defines editing and persistence guarantees. The [character creator contract](2026-10-12-character-creator-runtime.md) defines the current controls, appearance, randomization, and section membership.

## [ES-form] Edit the selected living person

Edit opens the creator with the selected person's exact stored values. The pages are Identity, Appearance, Personality, Needs & habits, Interests & skills, Household, and Review. Apply changes submits one edit. Cancel and Escape discard the draft. Navigation preserves it. The household stays paused while the editor is open, and closing restores focus.

Editing works in a full household. It preserves the permanent SimId, position, current need levels, career, funds, and action progress. Only explicitly changed character fields are submitted. Appearance, temperament, habits, interests, skills, and relationships are editable; opening a page does not replace their saved values.

Names in the roster, selected-person panel, and relationship rows refresh after acceptance. A refusal leaves the draft open with an explanation. Loading another world closes the draft and invalidates pending results from the old world.

## [ES-personality] Preserve exact saved behavior

The runtime stores personality effects rather than an archetype identity. The editor preloads those effects directly, including custom or historical values. A name-only edit preserves them exactly. Content tuning changes do not rewrite the saved person.

The optional Needs & habits preset explicitly replaces its documented fields: need rates, activity preferences, sleep timing, and cleanliness. Section Reset and Randomize follow visible field membership, not the grouping used by the save format. Reset restores the fixed defaults defined in the creator contract, including activity preferences of 1.0x. Unrelated and hidden legacy values remain unchanged. Undo restores the exact previous draft, including sparse activity records and historical values outside new-character slider ranges.

Activity categories show the arithmetic average of effective member weights, including implicit defaults. Viewing an average changes nothing. Editing the category changes its members together in one undoable operation and preserves unrelated activity records.

Behavior-bearing fields participate in the deterministic world hash. Name and appearance changes do not consume simulation randomness. Each draft has its own seeded random generator, locks, and undo history.

## [ES-traits] Retained progress and removal

Retained traits keep their stored states unless the player explicitly edits a supported condition control. Unchecking and rechecking a trait within the same unsubmitted draft restores its last selected state and order, including explicit severity edits. Reset clears retained trait settings only in its scope; Undo restores them. A new trait starts from the applicable content default.

Committing a condition's removal discards its severity; later re-addition uses the content default. Skills store practice independently and survive removal of a capability trait. The interface does not display the rejected condition-removal implementation explanation.

An action already in progress keeps its duration, reservation, outcome roll, and existing mishap. Later calculations use the edited traits. A completed attempt adds practice to its matching skill even if the capability trait was removed. Removed conditions must not reappear merely because an older action finishes.

## [ES-atomic] One validated command

The versioned character patch contains only changed save groups. The simulation resolves the target and relatives by permanent SimId when commands drain. It rejects missing or retired identities rather than applying the edit to a reused entity slot.

Validation completes before any write or random draw. Invalid names, appearance identifiers, numeric values, content identifiers, trait limits, or relationships reject the whole edit. Reuse creation's value validation without its capacity and arrival requirements.

Relationship assignments replace only submitted pairs. Each pair uses canonical SimId ordering and the established inverse relationship rules. Unrelated pairs and ties to absent or deceased people survive. A name edit and its relationship edits cannot partly succeed.

Results identify the submitted request. Pending state clears on world replacement; stale results cannot complete a new draft.

## [ES-save] Save queued and accepted edits

Save version 10 combines social state, appearance, and character-edit records while retaining frozen historical layouts. Both published social version-9 saves and earlier local creator version-9 saves remain readable. Historical records without appearance receive the documented deterministic legacy appearance. Existing pronoun strings survive unrelated edits even though the interface no longer exposes them; new characters store an empty string.

Queued edits survive saving before command drain. Save content references as authored identifiers, not current pack positions. Invalid references reach the normal atomic validator and cannot become partial edits. Include pending edits in the deterministic world hash and preserve the random-generator state.

A load does not apply queued commands or advance time. Missing historical fields use their documented defaults. Truncated records, duplicate person entries, invalid numeric values, and unsupported current versions remain errors. Browser storage validates the same envelope version and retains recovery bytes when an older worker cannot read a newer save.

## [ES-evidence] Required checks

1. Edit starter and newly created people, including a full household. Verify permanent identities and unrelated gameplay state survive.
2. Preserve retained trait states and skill practice. Test draft toggles separately from committed removal and re-addition.
3. Preserve custom and historical behavior through unrelated edits, Cancel, and save/load. Verify Reset changes only its visible scope to defaults, Undo restores exact previous records, and explicit preset application changes only its declared fields.
4. Reject mixed valid and invalid patches atomically, including stale targets and relationships.
5. Verify each relationship direction, clearing one pair, and preserving unrelated pairs.
6. Save before command drain and after acceptance. Load historical fixtures and compare both exact edited fields and deterministic hashes.
7. Edit during object use, chains, conversations, and work. Preserve reservations, payouts, progress, and interruption behavior.
8. Exercise the actual desktop and narrow creator with keyboard and pointer input. Verify preloading, navigation, locks, undo, Reset boundaries, pending states, graphics recovery, and cancellation. Inspect screenshots as well as state assertions.
9. Introduce faults only in an isolated source copy or test browser. Require meaningful checks to reject them and verify exact restoration.

## [ES-code-map] Implementation paths

The browser draft and field membership live in `web/src/character/`. The interface and session lifecycle live in `web/src/ui/character-creator/` and `web/src/main.ts`. The browser bridge carries versioned projections and commands.

`crates/terri-core/src/character.rs` defines the command values. `crates/terri-sim/src/character_draft/` owns validation and application. `crates/terri-sim/src/save/v10.rs` preserves current character state and queued edits. The WebAssembly boundary is in `crates/terri-wasm/src/lib.rs`; browser storage version checks are in `web/src/storage/`.
