# Object affinities: things one housemate loves can bother another

Status: implemented on branch `twcl/object-affinities`; the evidence is in `2026-10-06-object-affinities-verification.md`. This is the first slice of [B-object-affinities] in `docs/FEATURES.md`. It gives every person a feeling about each kind of thing that a reasonable person could love or hate, lets those things in the room move mood, and lets somebody else's television bother a person who hates television. Colour preferences [B-colour-preferences], novelty from purchases ([S-acclimation] part two), sensitivities [S-sensitivities], the general nuisance field [P-nuisance] and editing the values are later slices.

## [OA-kinds] Which kinds of thing carry an affinity

Content names the kinds. `content/objects.toml` gains `[[affinity]]` tables beside the colourways, each with an id, a label a player reads, how it reaches people (`reach`, either `presence` or `use`), the object ids it covers, and optionally the trait tag whose disposition traits set a strong starting value. An object no kind lists carries no affinity, so a sofa, a fridge and a bed never please or bother anyone through this system. The shipped kinds are plants (`presence`, the potted plant), the aquarium (`presence`, the aquarium), television (`use`, the television, trait tag `television`) and the radio (`use`, the radio). The compiler refuses a kind id listed twice, a blank label, an unknown reach, an object id no object has, an object covered by two kinds, a `use` kind covering an object that has no interaction, and a trait tag no activity carries, and it keeps the file order of the kinds as the order of every per-person list.

"Avoids the couch" stays a trait about using sofas and armchairs; the sofa carries no affinity, as the roadmap entry says.

## [OA-values] Every person has one value per kind

Each person holds one value from -1 (hates) to 1 (loves) for each kind, in kinds order. The value is drawn once when the person is created, uniformly from the seeded world generator, kind by kind, right after the Self-preservation draw, so the shipped household and every new housemate get the same values on every replay of the same seed. A worn disposition trait whose tag is the kind's trait tag replaces the draw for that kind with a fixed strong value, `affinity_from_trait` (0.8) for a trait that loves (its multiplier is at or above `affinity_loves_from`) and its negative for a trait that hates (at or below `affinity_hates_to`); the draw is still taken so the generator sequence does not depend on which traits are worn. Editing a person's traits later does not change the stored value; changing the values is [S-advanced-controls] work.

The values are saved as one more appended field of the V5 envelope, rows of `(entity index, kind id, value)` sorted by entity index, exactly as skills are saved. A save written before this slice has no field and gets values seeded once after load, in entity-index order from the saved world generator, so the same old save always seeds the same household. A save older than both Self-preservation instincts and affinities seeds every missing instinct first and then every affinity value, each in entity-index order, rather than interleaving them per person as spawning does. A present field is authoritative, and load refuses a row that names a dead person, an unknown kind or a value outside -1 to 1. The values join the world hash as a sparse tagged block, `affinities-v1`, present only when a person holds a value other than zero.

## [OA-presence] Things in the room move mood

Every tick, for each living person inside the house, the game counts the objects of each `presence` kind in the person's room (the room regions the relationship system already uses; the yard is no room, so nothing outside counts). A kind with at least one object and a value at or beyond `affinity_presence_threshold` (0.2) in either direction gives one derived moodlet, `Likes the plants here` or `Bothered by the plants here`, worth `value * (affinity_presence_points + affinity_presence_extra_points * min(count - 1, affinity_presence_extra_cap))`. The shipped numbers are 10 points, 3 extra points and a cap of 3, so a person who loves plants at 1.0 reads +10 beside one plant and +19 beside four. Nothing is stored: the moodlets are derived like `Dirty dishes`, and they come after `Feeling sick` in the list. A person at work counts as outside the house: while they are away their position stays where they left the lot, which is the street's exit in the yard on the shipped lot but the front door's tile, inside the living room, on a lot without a street. A person walking to or from work counts in whichever room they are crossing.

## [OA-use] Somebody else's use bothers a person who hates the kind

Every tick, for each living person inside the house with a value at or below `-affinity_presence_threshold` for a `use` kind, the game finds every other person in the same room who is actually using an object of that kind (standing at it with the interaction running, not walking to it). Each such person gives the bothered person one derived moodlet, `Bothered by {name} using the television`, worth `value * affinity_use_points` (15 points, so -15 at -1.0), and lowers the bothered person's feeling toward the user by `|value| * affinity_use_feeling_per_hour / 60` per tick (0.03 per hour), recorded with a new relationship cause, Nuisance, so the diagnostics name it. A person using the thing themselves is not bothered by their own use, a person who merely likes the kind gets nothing from another's use, and a person outside the house gets nothing. A person at work counts as outside the house here as in [OA-presence], whether they would be the one bothered or the one using. Nothing is stored beyond the feeling, which the relationship system already saves.

## [OA-hud] What the player reads

The Sim details Overview gains a collapsed section, `Likes and dislikes`, after Skills, with one row per kind in kinds order: the kind label and one word from the value, `Loves` at or above 0.6, `Likes` at or above 0.2, `Indifferent` between, `Dislikes` at or below -0.2, `Hates` at or below -0.6. The moodlets appear in the mood panel like every other derived moodlet. Functional text stays plain; the labels above are proposals for the owner's review under `docs/player-visible-strings.md`.

2. Values: the shipped household draws its values in entity order after the instinct draw and two worlds built from one seed agree; Bill, who wears Television devotee, holds 0.8 for television; a person wearing Hates television holds -0.8; a person without a television trait holds the drawn value; removing or adding a trait later leaves the stored value unchanged.
3. Save: a V5 save round-trips the values; a save written before this slice (the pinned released save) loads, seeds once in entity order, and seeds identically on a second load; load refuses a bad row; the wasm decoder pads one more appended list and the local-bed order is untouched; the world hash moves only through the new block, and a household with every value at zero hashes as before.
4. Mood: a person at 1.0 for plants reads +10 in the living room beside one plant and nothing in the yard; a person at -1.0 reads -10; a person at 0.1 reads nothing; four plants read +19 under the cap; the moodlet order places the new rows after `Feeling sick`.
5. Use: a person at -1.0 for television in the same room as someone watching reads -15 and their feeling toward the watcher falls by 0.03 over a 60-tick hour with a Nuisance cause recorded; a person walking to the television bothers nobody yet; the hater watching themselves is not bothered; a person in another room is not bothered; a person at +1.0 reads nothing.
6. Boundary and HUD: the values and labels cross the wasm boundary; the `Likes and dislikes` section renders in the fake DOM tests with the five words; a displayed check at desktop and phone widths shows the section and a presence moodlet, with screenshots.
7. Every existing golden, autonomy, relationship and save test still passes without weakening; the trace example still runs.
