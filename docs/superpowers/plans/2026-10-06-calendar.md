# Calendar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the game a seven-day week derived from the clock, let careers name their working days so the office job rests on weekends, and show the weekday and the job's schedule in the HUD.

**Architecture:** A pure function in `terri-core` maps a tick to a weekday from `day_ticks` and a tuning `first_weekday`. Careers gain a seven-bit `working_days` mask compiled from weekday names; `start_shift` adds one gate on that mask. The wasm boundary exports the current weekday index and a career schedule projection; the web clock and the Sim details Career row format them. Nothing is saved or hashed beyond what exists.

**Tech Stack:** Rust workspace (`terri-core` clock, `terri-data` schema and compiler, `terri-sim` career system, `terri-wasm` boundary), TypeScript web shell (Vitest fake-DOM tests).

**Spec:** `docs/specs/2026-10-06-calendar.md` ([CAL-week], [CAL-careers], [CAL-hud], [CAL-evidence]).

## Rulings

1. **Day 1 is a Monday** (`first_weekday = 0`), so days 1 and 2 stay working days and every existing day-1 and day-2 fixture and test keeps its meaning. Cost if wrong: the owner changes one tuning number.
2. **Working days are content, not saved and not fingerprinted**, like pay and hours. Cost if wrong: a later career slice that must freeze a worker's schedule into the save adds a field then.
3. **The weekday function lives in `terri-core`** and both the simulation and the boundary call it; the web shell never recomputes it.
4. **The clock reads `Day {n}, {Weekday}, {hh}:{mm}`** with full names; the Career row reads `{label}, {days}, {hh}:{mm} to {hh}:{mm}` with `Monday to Friday` for a contiguous run.
5. **Dated evidence records are not rewritten** (the 120000-tick trace funds and hashes, the autonomy validation table): they describe what was true when written.

## Global Constraints

- `terri_core::clock::weekday(tick: u64, day_ticks: u32, first_weekday: u8) -> u8` returns 0 (Monday) to 6 (Sunday) as `((tick / day_ticks) + first_weekday) % 7`; `day_ticks` is validated non-zero at compile time (existing `ZeroDayTicks`).
- Tuning `first_weekday: u8` in `0..=6` (error `FirstWeekdayOutOfRange`); careers `working_days: Vec<String>` of names `mon tue wed thu fri sat sun`, at least one, no repeats, unknown names refused (errors `EmptyWorkingDays { id }`, `RepeatedWorkingDay { id, day }`, `UnknownWorkingDay { id, day }`); compiled `CompiledCareer.working_days: u8` mask with bit 0 = Monday.
- `start_shift` gates the existing `clock.tick % day_ticks == career.shift_start` with `career_works_on(career, weekday)`; the gate is a small `pub(crate) fn` in `career.rs` so a concurrent rewrite of the filter keeps one line to merge. The `debug_assert_eq!` stays.
- No new save field; the world hash code is untouched; the bare-agent golden vector, the aquarium pin and every historical fixture are unchanged; the content fingerprint is unchanged; `GOLDEN_PACK_BYTES` in `compile.rs` is regenerated because `Tuning` gained a field (append order) and the regeneration is explained in the commit.
- Every `CompiledCareer` and `CareerDef` literal in tests gains `working_days` (career.rs `a_career`, edit_tests.rs, portals.rs, pack.rs round-trip fixtures, compile.rs `a_career`), set to all seven days where the test's day count would otherwise cross a weekend, and to Monday to Friday where the test is about the shipped job.
- Tests never `while` on simulation state. Guard deletions per lesson [L15], recorded in `docs/specs/2026-10-06-calendar-verification.md`.
- Functional text plain; strings inventory and glossary updated; no em dash or en dash anywhere new; imperative commit messages; no attribution; commit with `git -c user.name="Tim Woodruff" -c user.email="myemailaddressisveryclever@gmail.com" commit ...`; stage only files you change.
- Before each commit: `cargo fmt --all`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`; for web tasks `wasm-pack build crates/terri-wasm --target web --out-dir ../../web/src/wasm`, then from `web/`: `npm run typecheck`, `npx vitest run`, `npm run build`; plus changelog tests and build and `py -3 check-doc-ids.py` on the final task.
- Three other worktrees hold unmerged work: one rewrites the `start_shift` filter and one counts weeks from day index 0 (consistent with Ruling 1). Do not read or copy from them.

## Review Focus

1. **A worker whose shift starts at tick 0 of the day** (test careers use `shift_start: 0`) on the first tick of a weekend day must not leave; the gate reads the weekday of the advanced tick, which `start_shift` already sees after `advance_clock`. Pinned in Task 2 (`a_shift_at_midnight_respects_the_weekday_of_the_new_day`).
2. **A worker already at work when a weekend begins** finishes and is paid. Pinned in Task 2 (`a_shift_running_into_the_weekend_still_pays`).
3. **A save written on a weekend with a worker commuting home** loads and the worker returns; the next shift waits for Monday. Pinned in Task 2 (`a_weekend_commute_loads_and_the_next_shift_waits_for_monday`).
4. **`first_weekday` 6 (day 1 is Sunday)** makes the shipped job's first shift happen on day 2; the HUD on day 1 reads `Sunday`. Pinned in Task 1 (weekday arithmetic) and Task 2 (shift test with the tuning overridden through `pack_tuned`).
5. **A nonstandard `day_ticks`** (the web test's 100-tick day) still maps weekdays by whole days. Pinned in Task 1 (`weekday_counts_whole_days_of_any_length`).
