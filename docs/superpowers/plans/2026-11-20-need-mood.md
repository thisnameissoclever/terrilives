# Gradual mood changes from needs

The approved need rules are in [the mood specification](../../specs/2026-08-01-moods-and-moodlets-design.md#m2-need-rules). Apply them to each surviving person once per completed simulation minute. Combine simultaneous gains and losses before clamping. Keep the contribution in integer units so each minute and a save round trip retain the smallest gain exactly.

1. Exercise the threshold crossings, several needs together, both limits, pause and new people in native simulation tests. Replace the old instantaneous mood contributions in the same projection used by the HUD, careers, chores and life satisfaction. Keep independent need warnings and urgency decisions.
2. Store nonzero contributions in a version 27 envelope that includes the entire Career version 24 save. Check ordinary load, exported saves, build transactions, malformed records and protection of the original browser slot, including editable-world versions 24, 25 and 26. Start older households at zero.
3. Replay the affected household from a copy and compare living Sims’ time at maximum mood across several game weeks with a starter household. Measure actual overall mood as well as accumulated need points.
4. Update the player guide, compiled values and changelog. Verify Rust, WebAssembly and browser storage, complete independent review, then deliver the checked revision and verify the deployment.
