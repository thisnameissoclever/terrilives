# Local testing and publication delivery plan

**Goal:** Repair mutation runtime identity, keep substantive validation local, and shorten publication without removing game assertions.

**Authority:** The owner's paid-CI policy requires explicit approval before hosted testing, including work triggered by pushes or merges. Automatic Pages publication is the standing exception for relevant deployable inputs. Local verification and independent review remain required.

## Implementation

1. Keep one reviewed, digest-pinned mutation image for hosted jobs. Bind its compiler, executable, library, command resolution and recipe identities. Keep host metadata as separate provenance. Preserve immutable plans, authenticated recovery, eight shared slots and native spending admission.
2. Move routine Rust, web, artwork, documentation and script commands into the local runner. Record revision, commands, results and platform limitations. Retain all substantive assertions and bounded concurrency.
3. Remove automatic hosted validation triggers. Require an exact owner-reviewed local revision and evidence reference for an explicitly approved manual dispatch. Provide plan-only execution that cannot start native measurement or workers.
4. Start Pages directly for main pushes changing declared deployable inputs. Share those inputs with the stale-release classifier. Exclude unrelated tests, testing tools, engineering documentation and metadata.
5. Build WebAssembly once during publication. Preserve exact source selection, manual exact-main validation, complete site checks and the sparse current-main comparison. Refuse stale or unknown publication inputs.
6. Review final changes independently. Complete local checks against a stable tree before delivery. Obtain separate approval before any hosted test, rerun, or action that would trigger unapproved compute.
7. Merge the reviewed changes, synchronize the task checkout with remote main and verify actual publication when deployment inputs changed. Distinguish local results, optional hosted integration evidence and physical iPhone acceptance.

## Evidence and limits

Keep command output, checked revisions, measurements and temporary task status in ignored task evidence. Hosted qualification proves the optional remote orchestration; it supplies no game mutation coverage. Local tests can prove recovery logic and actual child-process behavior, while remote service records require a separately approved hosted integration check. A locally passing build does not establish deployment or recovery on an affected iPhone.

## Ownership

1. CI worker: manual workflow, local runner, local command preservation and workflow policy tests.
2. Publication worker: Pages triggers, deployable input classifier, stale-release and publication routing tests.
3. Primary assistant: integration, maintained operational docs, verification evidence, independent review, authorized delivery and publication checks.
