# Edit Sims Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the player change a living person's name, personality, traits and family ties through one validated simulation command, reached from an Edit button beside the selected person, reusing the two-page New housemate form.

**Architecture:** A new append-only `SimCommand::EditHousemate` (wire code 22) targets a person by permanent SimId and is applied at the exclusive command drain by a new `terri-sim` module `edit.rs`, which validates the whole payload before writing anything. Personality effects (drain, satisfaction, dispositions) become part of the deterministic world hash because they are now runtime-editable; the authored archetype is derived at read time by exact match against current content rather than stored, so no new save field is needed. The web form gains an edit mode, prefilled from existing projections plus one new wasm export that reports the matching archetype.

**Tech Stack:** Rust 2021 workspace (`terri-core`, `terri-sim`, `terri-wasm`, `terri-data`), bevy_ecs, postcard wire format, wasm-bindgen via wasm-pack; TypeScript web shell under `web/` built with Vite 8 and tested with Vitest 4; cargo-mutants in CI.

**Spec:** `docs/specs/2026-09-30-edit-sims.md` (sections [ES-form], [ES-personality], [ES-traits], [ES-atomic], [ES-save], [ES-evidence], [ES-code-map]). The plan argues from the spec; where the spec left a choice open, the ruling is recorded in **Rulings** below and must be carried into the spec's status section in Task 7.

## Rulings

These settle the choices the spec left open. Each is reversible later; each is recorded for the owner to overturn.

1. **Removed-trait policy: reset on re-add** ([ES-traits] alternative 2). A trait removed in a committed edit loses its state; adding it back in a later edit starts it at its authored level, severity, or zero. The form says so in plain text beneath the trait list in edit mode. Reason: it adds no persisted state, so the owner can still choose the inactive-ledger policy later as an appended save tail without migrating anything; the ledger policy would have to be kept forever once shipped. Cost if wrong: a player who removes and re-adds a capability loses its learned level in the meantime.
2. **No stored personality identity.** The archetype shown in the editor is derived at read time: the person's complete effects (drain, satisfaction, dispositions, chronotype offset) must equal exactly one current archetype, otherwise the editor shows "Keep current personality" as the only current choice. This satisfies [ES-personality]'s "exact match" rule and "rebalanced archetype" rule with no new save field. Cost if wrong: two archetypes with identical effects would be indistinguishable, which is not the case in shipped content.
3. **Personality effects join the world hash as a sparse tagged block**, written only for entities that carry a `Personality`, so the bare-agent golden hash vector is unchanged. Names stay out of the hash.
4. **Satisfaction offsets are not reapplied.** Trait starting-satisfaction offsets apply once at move-in; editing traits does not change Satisfaction.
5. **Cleanliness follows an explicit personality change.** The person's row in `SavedDomestic.cleanliness`, if present, is set to the new archetype's cleanliness; a name-only or keep-personality edit leaves it untouched.

## Global Constraints

- Append-only wire format: `SimCommand::EditHousemate` is variant 22 and `SavedCommand::EditHousemate` is appended at the same position; never reorder existing variants (`crates/terri-core/src/command.rs:19-33`).
- No new V5 save-envelope field. The queued edit is saved through `SavedCommand`, inside the frozen `SaveSnapshotV1.queued_commands`; content references in saved commands are authored ID strings, never pack indices.
- `SimName` is never read by `world_hash` (`crates/terri-core/src/components.rs:781-782`).
- Every behavior-bearing personality field (drain, satisfaction, dispositions, chronotype offset) is in the world hash after this plan; the chronotype block `chronotype-offsets-v1` already exists and stays as it is.
- Validation rejects the whole command before any write or random draw; a refused edit changes neither the world hash nor the save bytes.
- Name bounds: trimmed, non-empty, at most `tuning.housemate_name_max_chars` (24) characters. Trait bounds: at most `tuning.housemate_max_traits` (4), each index below `content.traits.len()`, no repeats. Tie bounds: at most `MAX_HOUSEHOLD_SIZE` (6) entries, relation codes 0 through 3 or none (code 4 at the wasm boundary), no self-tie, each relative once, each relative a living person.
- Functional interface text stays plain (`docs/player-visible-strings.md`, lesson [L58]): button labels and refusal lines say exactly what happens, with no jokes.
- No em dash (U+2014) or en dash (U+2013) anywhere in new code, strings, comments, documentation or commit messages.
- Every player-visible string added goes into the inventory in `docs/player-visible-strings.md` and gets a `docs/glossary.md` entry where it introduces a term.
- Tests that pin a guard or a hash input are verified by deleting the mechanism and watching the test fail (`docs/testing-protocol.md` rule 1); record the four steps in `docs/specs/2026-10-05-edit-sims-verification.md`.
- Every production loop is bounded; none of the new loops may be unbounded (they iterate over bounded `Vec`s only).
- A test never waits on simulation state with `while` or `loop` (lesson [L-a-test-that-waits-must-be-bounded]): tick a fixed count with `for`, then assert the state.
- Guard-deletion checks follow lesson [L15]: write command output to a file, restore the original bytes in a `finally` block, and prove restoration with `git hash-object <file>` against the pre-mutation value. A compile error is not a caught mutation (lesson [L-mutation-compile-baseline]); only a named test failing on an assertion counts.
- `cargo mutants` runs only in remote CI on the pull request; it is additional evidence, not a local gate. Run `cargo test` for the crate you changed while iterating and `cargo test --workspace` once before each commit.
- Commit messages begin with an imperative verb and carry no tool or vendor attribution.
- Rust tests run from the repository root with `cargo test -p <crate> <filter>`; web tests run from `web/` with `npx vitest run <file>` after `wasm-pack build crates/terri-wasm --target web --out-dir ../../web/src/wasm`.

## Review Focus

1. **A person mid-action loses a capability trait in an edit.** The action should finish normally and must not recreate the removed trait at completion. Test pinned in Task 2 (`removing_a_trait_mid_action_does_not_recreate_it_at_completion`).
2. **An edit is queued, then the player loads another save before the drain runs.** The old world's result must not complete the new world's draft. Test pinned in Task 5 (`a load while an edit is pending closes the draft and ignores the old answer`).
3. **A name of only spaces or of 25 characters** must be refused with "Give them a name that fits." and leave the person unchanged. Test pinned in Task 2 (`every_invalid_field_refuses_the_whole_edit_without_writing`).
4. **A tie to a dead person** must survive an edit that changes ties among the living. Test pinned in Task 2 (`ties_to_the_dead_survive_an_edit_of_living_ties`).
5. **Hostile numbers at the boundary in a release build** (NaN, infinity, negatives, fractions, 2^32, odd-length tie arrays, relation code 5) must return false without touching the world. Test pinned in Task 4 (`edit_boundary_rejects_hostile_numbers_in_release`).

    if personality as usize >= content.personalities.len() {
        return Err(HousemateRefusal::UnknownPersonality);
    }
    validate_traits(content, traits)?;
    Ok(name)
}

/// The trimmed name, non-empty and within the tuned character limit.
pub(crate) fn validate_name(
    content: &terri_data::ContentPack,
    name: &str,
) -> Result<String, HousemateRefusal> {
    let name = name.trim();
    if name.is_empty() || name.chars().count() > content.tuning.housemate_name_max_chars as usize {
        return Err(HousemateRefusal::BadName);
    }
    Ok(name.to_string())
}

/// At most the tuned count, every index known, none repeated, in that order.
pub(crate) fn validate_traits(
    content: &terri_data::ContentPack,
    traits: &[u32],
) -> Result<(), HousemateRefusal> {
    if traits.len() > content.tuning.housemate_max_traits as usize {
        return Err(HousemateRefusal::TooManyTraits);
    }
    if traits
        .iter()
        .any(|&index| index as usize >= content.traits.len())
    {
        return Err(HousemateRefusal::UnknownTrait);
    }
    if traits
        .iter()
        .enumerate()
        .any(|(at, index)| traits[..at].contains(index))
    {
        return Err(HousemateRefusal::RepeatedTrait);
    }
    Ok(())
}

/// A worn trait's opening state ([E3]): a capability at its start level,
/// a condition at its start severity, a disposition stateless at 0.
pub(crate) fn authored_trait_state(worn: &terri_data::CompiledTrait) -> f32 {
    match worn.kind {
        terri_data::CompiledTraitKind::Capability { start_level, .. } => start_level,
        terri_data::CompiledTraitKind::Condition { start_severity, .. } => start_severity,
        terri_data::CompiledTraitKind::Disposition { .. } => 0.0,
    }
}

//! [ES-atomic]: editing a living person in place. One command carries the
//! complete new identity; it is checked whole before anything is written,
//! and the person keeps their SimId, needs, position, career, hobbies,
//! satisfaction, relationships, instinct and mortality records.

use terri_core::{Agent, Personality, SavedDomestic, SimId, SimName, Traits};

/// Why an edit was refused, in the order the checks run. The numbers are
/// the codes the boundary reports.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
#[repr(u8)]
pub enum EditRefusal {
    UnknownPerson = 1,
    BadName = 2,
    UnknownPersonality = 3,
    TooManyTraits = 4,
    UnknownTrait = 5,
    RepeatedTrait = 6,
    UnknownRelative = 7,
    RepeatedRelative = 8,
    SelfTie = 9,
}

impl From<HousemateRefusal> for EditRefusal {
    fn from(refusal: HousemateRefusal) -> Self {
        match refusal {
            HousemateRefusal::BadName => Self::BadName,
            HousemateRefusal::UnknownPersonality => Self::UnknownPersonality,
            HousemateRefusal::TooManyTraits => Self::TooManyTraits,
            HousemateRefusal::UnknownTrait => Self::UnknownTrait,
            HousemateRefusal::RepeatedTrait => Self::RepeatedTrait,
            // The shared helpers never return these; the edit path does not
            // run arrival or capacity checks.
            HousemateRefusal::HouseholdFull
            | HousemateRefusal::NoWayIn
            | HousemateRefusal::BadInstinct => Self::UnknownPerson,
        }
    }
}

/// The drain's answer to one edit. `sim` is the edited person's entity
/// index when accepted. `handled` numbers every answer so the shell can
/// tell its own edit's answer from an older one.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct EditResult {
    pub sim: Option<u32>,
    pub reason: Option<EditRefusal>,
    pub handled: u32,
}

/// One edit as the drain sees it; borrowed from the command.
#[derive(Debug, Clone, Copy)]
pub struct Edit<'a> {
    pub sim: u32,
    pub name: &'a str,
    pub personality: Option<u32>,
    pub traits: &'a [u32],
    pub ties: &'a [(u32, Option<Relation>)],
}

/// The living person with this permanent SimId, if there is one. The dead
/// keep their SimId in records but have no `Agent` entity.
pub fn living_entity(world: &World, sim_id: u32) -> Option<Entity> {
    let mut query = world.try_query::<(Entity, &Agent, &SimId)>()?;
    query
        .iter(world)
        .find(|(_, _, id)| id.0 == sim_id)
        .map(|(entity, _, _)| entity)
}

/// Checks the whole edit in [ES-atomic]'s order. Writes nothing.
pub fn validate(world: &World, edit: &Edit) -> Result<(Entity, String), EditRefusal> {
    let content = world.resource::<Content>().0;
    let entity = living_entity(world, edit.sim).ok_or(EditRefusal::UnknownPerson)?;
    let name = validate_name(content, edit.name)?;
    if let Some(personality) = edit.personality {
        if personality as usize >= content.personalities.len() {
            return Err(EditRefusal::UnknownPersonality);
        }
    }
    validate_traits(content, edit.traits)?;
    for (at, (relative, _)) in edit.ties.iter().enumerate() {
        if *relative == edit.sim {
            return Err(EditRefusal::SelfTie);
        }
        if living_entity(world, *relative).is_none() {
            return Err(EditRefusal::UnknownRelative);
        }
        if edit.ties[..at].iter().any(|(earlier, _)| earlier == relative) {
            return Err(EditRefusal::RepeatedRelative);
        }
    }
    Ok((entity, name))
}

/// Applies an accepted edit: the trimmed name, the kept or replaced
/// personality, the new trait set with retained states, and the submitted
/// tie pairs. Everything else about the person is untouched.
fn apply(world: &mut World, entity: Entity, name: String, edit: &Edit) {
    let content = world.resource::<Content>().0;
    if let Some(mut current) = world.get_mut::<SimName>(entity) {
        current.0 = name;
    } else {
        world.entity_mut(entity).insert(SimName(name));
    }
    if let Some(index) = edit.personality {
        let compiled = &content.personalities[index as usize];
        world.entity_mut(entity).insert(personality_from(compiled));
        if let Some(mut domestic) = world.get_resource_mut::<SavedDomestic>() {
            if let Some(row) = domestic
                .cleanliness
                .iter_mut()
                .find(|(index, _)| *index == entity.index_u32())
            {
                row.1 = compiled.cleanliness;
            }
        }
    }
    let current = world.get::<Traits>(entity).cloned().unwrap_or_default();
    let entries = edit
        .traits
        .iter()
        .map(|&index| {
            let state = current
                .state(index)
                .unwrap_or_else(|| authored_trait_state(&content.traits[index as usize]));
            (index, state)
        })
        .collect();
    world.entity_mut(entity).insert(Traits::from_entries(entries));
    if !edit.ties.is_empty() {
        if world.get_resource::<FamilyTies>().is_none() {
            world.insert_resource(FamilyTies::default());
        }
        let mut family = world.resource_mut::<FamilyTies>();
        for (relative, relation) in edit.ties {
            family.set(edit.sim, *relative, *relation);
        }
    }
}

/// Validates, applies when valid, and records the numbered answer.
pub(crate) fn commit(world: &mut World, edit: &Edit) {
    let result = match validate(world, edit) {
        Err(reason) => EditResult {
            sim: None,
            reason: Some(reason),
            handled: 0,
        },
        Ok((entity, name)) => {
            apply(world, entity, name, edit);
            EditResult {
                sim: Some(entity.index_u32()),
                reason: None,
                handled: 0,
            }
        }
    };
    let mut state = world.resource_mut::<LotEditState>();
    let handled = state
        .last_edit_result
        .map_or(0, |last| last.handled)
        .saturating_add(1);
    if result.reason.is_none() {
        state.revision = state.revision.saturating_add(1);
    }
    state.last_edit_result = Some(EditResult { handled, ..result });
}

            match placement_u32(personality) {
                Some(index) => Some(index),
                None => return false,
            }
        };

            .iter()
            .map(|&index| placement_u32(index))
            .collect::<Option<Vec<u32>>>()

            return false;
        };

            return false;
        }
        let Some(ties) = ties
            .chunks_exact(2)
            .map(|pair| {
                let relative = placement_u32(pair[0])?;
                let code = placement_u32(pair[1])?;
                let relation = match code {
                    4 => None,
                    code => Some(terri_core::layout::Relation::from_code(u8::try_from(code).ok()?)?),
                };
                Some((relative, relation))
            })
            .collect::<Option<Vec<_>>>()
        else {
            return false;
        };
        let bytes = postcard::to_allocvec(&SimCommand::EditHousemate {
            sim,
            name: name.to_string(),
            personality,
            traits,
            ties,
        })
        .expect("an edit serializes");
        self.enqueue_command(&bytes)
    }

    /// person's entity index or `u32::MAX`, and the answer number.
    pub fn last_edit_result(&self) -> Vec<u32> {
        self.sim
            .world()
            .resource::<terri_sim::placement::LotEditState>()
            .last_edit_result
            .map_or_else(Vec::new, |result| {
                vec![
                    result.reason.map_or(0, |reason| reason as u32),
                    result.sim.unwrap_or(u32::MAX),
                    result.handled,
                ]
            })
    }

    /// `u32::MAX` when the person's effects match no single archetype.
    pub fn personality_index_of(&self, index: u32) -> u32 {
        self.sim.personality_archetype_of(index).unwrap_or(u32::MAX)

import type { SimBridge } from '../bridge.js';
import { NO_RELATION } from '../bridge.js';
import type { HouseholdMember } from './household-roster.js';

/** Who a living person is right now, as the Edit housemate form shows them ([ES-form]). */
export interface EditTarget {
  readonly entity: number;
  readonly simId: number;
  readonly name: string;
  /** The archetype to mark as current, or null when only "Keep current personality" fits. */
  readonly personality: number | null;
  /** Active pack trait indices, ascending. */
  readonly traits: number[];
  /** Relation code from this person's side, keyed by the other person's SimId; NO_RELATION when none. */
  readonly ties: Map<number, number>;
}

export type EditTargetSource = Pick<SimBridge, 'simIdOf' | 'simName' | 'personalityIndexOf' | 'traitsOf' | 'familyTies'>;

/** Parent and child swap when read from the higher SimId's side ([FM-tie]). */
const MIRRORED: Readonly<Record<number, number>> = { 1: 2, 2: 1 };

function tieFrom(ties: Uint32Array, who: number, other: number): number {
  const low = Math.min(who, other);
  const high = Math.max(who, other);
  for (let at = 0; at + 2 < ties.length; at += 3) {
    if (ties[at] === low && ties[at + 1] === high) {
      const stored = ties[at + 2];
      return who === low ? stored : (MIRRORED[stored] ?? stored);
    }
  }
  return NO_RELATION;
}

export function editTargetOf(
  source: EditTargetSource,
  entity: number,
  others: readonly HouseholdMember[],
): EditTarget | null {
  const simId = source.simIdOf(entity);
  const name = source.simName(entity);
  if (simId === null || name === '') return null;
  const worn = source.traitsOf(entity);
  const traits: number[] = [];
  for (let at = 0; at + 1 < worn.length; at += 2) traits.push(worn[at]);
  traits.sort((a, b) => a - b);
  const family = source.familyTies();
  const ties = new Map<number, number>();
  for (const other of others) {
    if (other.simId === simId) continue;
    ties.set(other.simId, tieFrom(family, simId, other.simId));
  }
  return { entity, simId, name, personality: source.personalityIndexOf(entity), traits, ties };
}
