# Startup failure reports

The game keeps a bounded diagnostic journal throughout loading and play. It retains loading-phase history, recent console messages, interface actions, character download responses and completion, preparation operations, graphics-device errors and page lifecycle events. Records identify their time and operation. Active downloads, preparation and graphics work remain identifiable if the page stops before completion.

Errors remain recordable after the first completed frame. The latest error retains its actual name, message, bounded stack, cause chain, source location, worker details and selected HTTP evidence when present. Recent distinct errors remain in the journal; identical repeats carry a count. Repeated errors do not force synchronous storage writes every frame. Readiness records only completion of the first graphics frame; subsequent errors preserve that timestamp and identify their runtime stage.

Choose Report bug in Options to open an email draft to `bugreport@stfuai.com`. Email Tim on the failure card and [Startup report](https://thisnameissoclever.github.io/terrilives/startup-report.html) uses the same formatter. The subject is `[Bug report] Natural Causes vX.X.X`. Each action reads the latest records when activated. The body puts the actual error, build, browser, loading history and active operations before recent logs in newest-first order. If the latest attempt has no captured error, an older attempt's error is labeled as previous evidence.

The complete encoded mail link has an application budget of 8,000 characters, including recipient, subject, UTF-8 escaping and CRLF line endings. The formatter includes the newest records that fit, marks shortened error text, and reports omitted history. This is not a universal mail-client maximum. Neither [RFC 6068](https://www.rfc-editor.org/rfc/rfc6068.html) nor [Apple's Mail Links reference](https://developer.apple.com/library/archive/featuredarticles/iPhoneURLScheme_Reference/MailLinks/MailLinks.html) specifies a portable numeric size guarantee. The player reviews and sends the draft.

Copy debug details and Download report provide the larger retained JSON report. If copying is blocked, selectable text appears. The standalone page loads no game, simulation or graphics device. Reading or sharing there does not overwrite the saved attempt. Pretty-printed exports can exceed the compact storage limit. An unavailable mail application or a client that refuses the draft does not prevent copying or downloading.

The build reads its version from `web/package.json` and supplies it to the game HTML and standalone report through `web/startup-report/plugin.ts`. New attempts retain this version. For an older attempt without a recorded version, the report uses the current report-page version and labels that source explicitly; it does not assign that version to the older attempt. The sharing context also retains the visible failure-card summary and the reporting browser details. An active failure card can share its in-memory report when browser storage is denied.

An unfinished attempt means readiness was not recorded. Closing the page during loading also produces that state; it is not evidence of a browser crash by itself. A browser termination can preserve the last saved step while preventing JavaScript from recording its cause. A report saved before this recorder was deployed is unavailable. Reports in another browser or cleared storage are unavailable as well.

Character download failures retain selected delivery headers, the resource pathname and at most 1,024 response-body bytes. Error-body reading waits at most one second. Cookies, authorization headers and URL queries are excluded from this structured HTTP record. Errors forwarded through the preparation worker retain bounded response details in their message.

Error fields retain up to 2,048 message characters, 1,536 main-stack characters and 2,048 worker-stack characters, with bounded causes and explicit truncation metadata. Source coordinates accept finite numbers. Malformed or cyclic diagnostic values must not poison later persistence. Original console calls still run, and instrumentation rethrows the original application failures unchanged.

The compact saved report is bounded to three attempts and 32,768 serialized characters. Each attempt retains at most 80 recent log entries, six distinct recent errors and 24 loading phases. Storage pressure removes older attempts and historical error copies before recent logs. The latest actual error remains separate. Further pressure shortens detail with an explicit marker while preserving its message. Ordinary records are batched for up to 250 milliseconds; errors, loading phases and important graphics/preparation starts persist immediately. A five-second liveness timestamp and page lifecycle records supply context for interrupted attempts.

The recorder stores no household save and sends no data automatically. Known credential fields are excluded from structured console values; URL queries are excluded from structured resource paths. Browser storage denial or exhaustion must not prevent loading. An active game's copy/email controls use its in-memory journal when storage is unavailable. A selected response body is diagnostic material from the delivery service, so review the report before sharing it.

The recorder is a small classic script loaded before the game module. Its page and script remain separate from the game bundle. The current interface uses `startup-diagnostics-v3.js`; the original and v2 scripts remain published for cached HTML. The existing storage key and schema version accept optional journal fields. Application code sends bounded context through `web/src/diagnostics.ts`; the recorder owns serialization, storage and sharing. Preserve event compatibility when changing them.

The clipboard call runs directly inside the click handler, preserving the [user gesture required by WebKit](https://webkit.org/blog/10855/async-clipboard-api/). Email fields use the [`mailto` format](https://www.rfc-editor.org/rfc/rfc6068.html), including escaped header/body values and CRLF body line endings.

These reports supply missing observations. They do not establish the cause of an earlier iPhone failure or prove recovery on a physical device.
