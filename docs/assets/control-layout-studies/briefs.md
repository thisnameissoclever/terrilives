# Control layout mock-up briefs

These briefs accompany the three concept images. The screenshots in
`../review-evidence/sim-name-hierarchy/` supplied the visual reference.
The images are proposals for review; their layout dimensions and touch-target
sizes are design intentions, not verified measurements of an implemented UI.

## Household console

Create a realistic, production-quality UI design mock-up for Natural Causes, the isometric household life simulation game shown in the two attached screenshots. These images are reference material for the existing game, not a request to edit game art. This is ONE coherent design direction named "Household console", shown in matching desktop and mobile views on ONE clean design review sheet. Output a high resolution 2080 x 1160 landscape sheet. Main desktop frame is 1440 x 900; adjacent mobile frame is 390 x 844 at natural proportion. No phone bezel, OS status, browser chrome, perspective or device shadow. Label desktop and mobile outside their frames. Header: "Household console", small subtitle "Natural Causes / Controls study". Small footer "Concept for review". No option number.
Preserve the reference game's isometric room, furniture, sims, restrained purple-grey game art. Show its house large and recognizable in daylight; do not turn it into a different game or replace it with a cartoon landscape. Keep existing palette: surfaces #16161c, edge #2c2c36, text #d8d8e0, muted #9aa3ad, blue accent #6fb2d2, warnings #e58c85. Use system-ui sans-serif, body 14-16px, bold Sim names 20-24px. Flat surfaces, minimal dividers, 6px corners, subtle or no shadows. Game canvas is visually primary.
DESKTOP: Remove tall left sidebar. Put Time "Day 1, 14:32", Funds "0", and saved-status at upper left, Options upper right. Bottom full-width console about 190px tall, clearly grouped into household selection (Tim, Bill, Casey, Tim selected; New housemate smaller), prominent Tim identity and mood, seven compact clearly labeled horizontal need meters in two columns, and current action with Queue and Clear orders controls. Need labels Hunger, Energy, Hygiene, Bladder, Social, Fun, Comfort; do not add other stats. Put literal "Traits >" and "People >" as CLOSED disclosures, never expand trait content. A separate low bottom row within the same continuous console gives Pause, 1x, 2x, 3x plus Build. Main selected name Tim must be visually dominant. Do not duplicate controls in canvas.
MOBILE: Adapt same household console into a shallow bottom sheet, default compact (about 210px total including controls) while keeping at least half screen unobstructed game. Thin top status strip Time and Funds, Options. Bottom panel has visible Tim/Bill/Casey selector, Tim in bold with current activity, compact Hunger and Energy indicators and literal Needs disclosure for full seven meters, Traits CLOSED. Bottom controls Pause, 1x, speed disclosure, Build; all controls with at least44px touch height, no tiny dense 4-column text. Optional People in selected-person sheet, secondary actions in Options. Drag handle paired with a clear expand button, not gesture-only. Essential controls thumb reachable. Do not show all features on phone. Show a compact queue count if needed.
This is a focused play screen, not a dashboard. Prioritize grouping, type, whitespace, simple dividers over nested cards. All text crisp, functional, readable. No made-up game features or currencies or chat. In-game day/time are simulation data, not dates; current real date anchor September 30 2026 if any annotation date is used.
Footer outside screens: "All everyday controls in one place. Desktop trades some vertical space for constant access; mobile expands details on demand."

Include one small off-screen annotation outside the mobile frame "Needs opens a single full-width sheet" pointing to Needs button; no extra inset or second mobile screen. Traits is collapsed when that sheet opens; no visible trait descriptions.
Make the selected Sim name much more prominent than all secondary text. Use existing names only Tim Bill Casey. No invented features (no quests inventory chat map etc). No invented numeric currency symbols. UI copy plain, no jokes. Text must be crisp with no clipping, never stretch the screenshots. Simulation time not calendar time; real date anchor September30 2026 only if needed.
Footer outside frames: "Frequent controls stay at the bottom; details keep their own space. Less desktop height lost, but mobile needs one extra tap for detail."

## Context tray

Design realistic, production-quality game UI for "Natural Causes", using the attached desktop and mobile screenshots as visual grounding for its actual isometric house, characters and dark interface. Create ONE independent design direction called "Context tray" shown consistently on desktop AND mobile within ONE 2080 x1160 landscape review sheet. Desktop view1440x900 on left, mobile390x844 on right with natural proportions. Plain sheet backdrop, title "Context tray", subtitle "Natural Causes / Controls study", and tiny "Concept for review". Label Desktop and Mobile outside frames. No option number, device bezel, OS bars, browser chrome, perspective or decorative shadow.
Core design system matches source: near-black#16161c panels, border#2c2c36, text#d8d8e0, secondary#9aa3ad, restrained blue#6fb2d2, salmon#e58c85 for urgent needs only. Readable system sans body14-16px. Selected Sim name bold24px, household names bold16px. Spacing and dividers before borders, no nested cards. Preserve reference isometric furniture, rooms and figures, neutral daytime view. Keep house as hero.
DESKTOP: Minimal Time/Funds status in upper left; Options upper right. No left sidebar. Bottom is ONE wide floating anchored control tray with16px inset. Top row of this bottom tray has household selector Tim/Bill/Casey at left, bold selected name Tim center with brief activity "Reading", and visible tabs "Needs", "Actions", "People"; Needs selected. Under it is one short horizontally organized detail surface: seven compact labeled needs bars arranged in two rows, small Mood readout, and a clearly CLOSED "Traits >" row on right. Bottom-most strip Pause,1x,2x,3x and Build; keep at least all common controls instantly available. Height about165px. Avoid duplicating selected Tim name in three places; prominent identity and selector are sufficient. A single compact Now/Next strip just above tray can show "Reading" then "Eat" without extra buttons. Select a tab replaces detail area instead of stacking panels. Other global save/load controls stay under Options.

Show it in expanded NEEDS state, approx bottom330px of844px screen, leaving meaningful house view above. Top of sheet has big Tim, smaller Reading, close/collapse chevron44px target. Household selector Tim Bill Casey in44px row. Tabs Needs / Actions / People. NEEDS selected displays seven labeled meters in two columns, labels readable no abbreviation; Mood compact; Traits closed, no trait text. Lowest44px toolbar Pause,1x,speed disclosure,Build. Thin top status Time "Day1,14:32", Funds0, Options. Safe-area spacing bottom. Mobile tabs accessible by thumb. Do not show a second device or unrelated screen.
All labels functional, only features already in reference app: Time Funds Pause1x2x3x household members Needs Mood Traits People Actions Queue Clear orders Build Options. Need names Hunger Energy Hygiene Bladder Social Fun Comfort. Mock values can be illustrative, current time is simulation time not date; real current date September30 2026 if required for annotation. No social feed, currencies, badges, XP or new game mechanics.
Outside frames footer: "One detail area changes with the selected tab. The clearest house view, at the cost of hiding some information behind a tap." Crisp typography, well spaced and finished product UI.
