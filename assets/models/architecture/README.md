# Architecture room candidate

This is the first-room feasibility checkpoint for the approved windows, walls and floors plan. The nine window concepts remain approved. The owner accepted candidate08 wall and floor appearance in the actual renderer. The technical review remains separate from that appearance approval.

`geometry.py` describes solids in game coordinates. Wall height is 2.0 units, thickness is 0.12, and the baseboard is 0.14 high. Sash, Sliding and Picture retain widths 1, 2 and 3. `clip` physically cuts geometry at height 2/3; it does not hide an upper frame behind a transparent rectangle. Straight segments bevel only edges running along the wall, so neighboring panels meet on their exact authored end planes.

`render_review.py` opens the accepted Sim rig without saving it. Reference meshes and curves move into a render-hidden collection because their visibility drivers can override individual `hide_render` flags. The camera, lighting and toon materials come from that scene. No furniture or Sim source is edited. The camera measures approximately (32,21), (-32,21) and (0,-34.1467436) pixels per source unit. Architecture Z is calibrated by 1.1128440372 so its existing game height remains exactly 38 pixels per world unit; the camera and reference sprites keep their accepted scale.

The exporter emits both axes at full and cut heights for straight walls, corners, doorways, Sash, Sliding and Picture, plus two long review walls and three floor materials. Every color texel has a matching signed R16Float depth value containing local game X + Y. Camera rays intersect the evaluated beveled geometry. Planar cap and side corner normals must agree with their face normal (dot product above .9999). A Weighted Normal modifier is deliberately absent: it blended closed segment ends into otherwise flat caps and repeated a false shade band at each join. Antialiased fringe texels inherit a nearby covered surface owner. The color/depth pair is sampled at the same nearest texel in the renderer. Architecture color does not bake daylight, scenery or floor shadows.

`pack_review.py` checks the completed background receipt and exact output hashes, refuses clipped source images, and crops with registration intact. Floor materials first derive an exact half-open tile footprint, then extend material color into a small opaque texture apron. The vertex shader projects canonical world-grid corners into a physical diamond, so the apron changes no tile dimensions or heights. Adjacent tiles compute identical shared endpoints; the hardware triangle fill rule owns coverage. This avoids both partial-alpha blending seams and holes caused by nearest-texel rounding at integer camera origins. Ordinary architecture keeps paired color/depth texel ownership. Boards have staggered ends, Tiles have thin grout and Carpet has no permanent grid.

### Registration handoff to Tasks 6 and 7

`assets/sprites/gen/build.py` owns `web/src/render/architecture-data.ts` and content-addressed public resources. It appends logical IDs 1700 through 2171 after all 1,700 historical records. It preserves the existing `atlas.ts`, `atlas.toml`, PNG, old UV rectangles and decoded sprite pixels. A digest binds the complete historical sequence of names, dimensions and RGBA pixels. The generated module has no handwritten runtime behavior; `architecture.ts` remains available for Task 6 lookup logic. `architecture-atlas.ts` retains the Task 1 runtime texture interface.

Each descriptor carries `geometryKey`, model ID, width, direction, height mode, physical and logical bounds, source crop, density, origin, anchor and owned span. Window `ownedSpan` is a zero-based unit along increasing world X or Y, regardless of front/back view; subtract half the model width to find its local interval. Junction owners are east, south, west, north in that order. `armHeights` uses 0 absent, 1 cut and 2 full. Floor phase is `[x mod 4, y mod 4]`, including negative coordinates; all floor variants share physical geometry key `floor.tile` and identical depth. Sprite `x/y/w/h` refer only to the separate architecture textures. `depthRegistration` repeats the paired rectangle, origin and density, and must agree exactly.

Accepted-color mode loads historical atlas + architecture RGBA color + R16Float depth. Finish mode replaces the architecture color texture with its neutral RGBA carrier and adds an R8 role texture. Its four reserved sampled-texture slots are historical atlas, depth, carrier and roles. It does not retain the accepted-color texture in that binding layout. Up to twelve independently resident pattern textures fit the actual device limit of sixteen sampled textures; the initial seven patterns use eleven slots including those four. The role texture is single-channel integer data: 0 transparent/unowned, 1 wall finish, 2 floor finish, 3 frame, 4 glazing, 5 independent trim. Only roles 1 and 2 receive a finish. Other carrier pixels retain their independently authored materials.

The carrier renders finish-owned surfaces with neutral material. It contains no accepted floor plank ends, grout, carpet weave or floor hue. Pattern resources contain linear RGB authored variation and are sampled nearest; their row zero is the lower row in authored world coordinates. Floor pattern coordinates use `(worldX + .5, worldY + .5) / 4` modulo one. Wall coordinates use world `X + Y` and Z with each pattern's declared period. Geometry identity, pattern identity and palette identity are separate; choosing another palette cannot allocate another geometry/depth set. The catalogue may contain thousands of finishes while the active resource selection stays bounded. The two extra patterns and two extra palettes are unshipped test fixtures, not a new finish library or painting UI.

For a cropped texel center `(px,py)`, density `d`, registered origin `(ox,oy)` and decoded local depth `s`, reconstruct local coordinates with:

```text
screenX = (px + 0.5) / d - ox
screenY = (py + 0.5) / d - oy
x = (s + screenX / 32) / 2
y = (s - screenX / 32) / 2
z = (21 * s - screenY) / 38
```

Add the placement's world origin before selecting a pattern phase. Split pieces retain the same original texel depth and crop-relative origin, so reconstruction is exactly invariant under cropping. Half-float depth remains quantized; for wall sums below two, its maximum rounding error is 0.00048828125 world units, with half that error in reconstructed X and Y. Do not introduce a second eight-bit UV quantization. Floors use the renderer's canonical world diamond coordinates instead of this depth reconstruction. Tests pin exact world phase identity at shared X/Y endpoints, wide spans and corners, identical crop reconstruction from the same quantized depth, and periodic pattern wrap. Final shader sampling and joined appearance still need the Task 6/7 GPU proofs.

Accepted floor color already includes the desired starter hue. `authoredContentLook` records the unchanged content tuning that accompanied that art. For new architecture, apply current content relative to that baseline: hue difference, strength ratio and lightness difference. The unchanged content produces `[0,1,0]`, an identity color transform; `writeColourway` later stores strength minus one as usual. Apply a palette once to the neutral carrier/pattern result, then this relative content transform. Historical art keeps its existing absolute transform path. No content, save or simulation fingerprint changes are part of this export.

The 2048-by-2926 geometry atlases use 35,954,688 resident bytes for accepted RGBA color plus depth, or 41,947,136 for carrier plus roles plus depth. Seven 256-by-256 RGBA patterns bring finish mode to 43,782,144 bytes. A fixture catalogue with 1,007 finishes and two active patterns uses 42,471,424 bytes. Catalogue growth alone allocates no additional texture. Runtime selection must pass its actual slot cap (twelve for this layout) to the resource-budget validator; the generic helper can also validate other explicitly supplied limits. These counts exclude the unchanged historical atlas, GPU allocation padding and temporary upload buffers. Actual device limits are retained in `docs/assets/review-evidence/architecture/full-set/device-limits.json`; the requested device's texture dimension ceiling is 8192 even though the adapter advertises 16384.

### Reproduction and checks

1. Run the architecture Python suite. Launch `render_batch.py` through the existing hidden two-thread Blender command, with a new absolute output directory. Require `proof.json` state `complete` and all 174 records; launcher exit alone is not success.
2. Run `export_batch.py SOURCE NEW_EXPORT_DIRECTORY`. This uses the NumPy already bundled with the Blender authoring environment and Pillow in the existing local authoring environment. No dependency was added to CI; portable import and generator tests use Python's standard library and the existing Pillow dependency.
3. Run `review_batch.py SOURCE NEW_EVIDENCE_DIRECTORY`. Inspect all nine original and native sheets and the junction, straight, doorway and floor sheets. Record independent source-art acceptance against the exact manifest in `review.json`.
4. Point `architecture.json` to that reviewed package. Run the generator, then `python -B assets/sprites/gen/build.py --check`. The importer verifies the receipt, source hashes, contact assertions, complete catalogue, split reconstruction, masks, paired dimensions, depth registration and resource hashes before producing generated registration.
5. Run `python -B -m unittest discover -s assets/models/architecture -p 'test_*.py'` and the equivalent suite under `assets/sprites/gen`. `check_architecture_mutations.py OUTPUT_JSON` changes one production mechanism at a time. It requires a passing baseline target, a passing clean-input control while mutated, failure of the exact intended target without test errors, byte-identical restoration and a passing restored target. It checks eleven mechanisms, including material classification and carrier selection. Never run that mutation command concurrently with another importer, renderer or generator invocation.
